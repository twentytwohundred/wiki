### PR #213 ... onboarding picker polish (Phase F §12 step 5)

Adds a "why matched" inline tooltip.

- `CapabilityCard` component replaces the `<label className=capabilityRow>` row. Whole-card click target via a wrapping `<label>`; the checkbox is visually-hidden but kept in the focus order for keyboard + screen-reader access.
- Selection state visualised by an accent-tinted background + filled check badge (selected), dashed border + empty badge (default-on but operator opted out), or 0.72 opacity until hover (speculative, default-off). Hover lift via 1px translate + `--shadow-1` + line-strong border.

  - High: `Strong match (N tags). On by default; uncheck to skip its walkthrough.`

- Click on the `?` `preventDefault + stopPropagation`s so reading the tooltip doesn't toggle selection. Keyboard-revealable via `:focus-visible::after`.
- `aria-label="Why matched?"` on the trigger; `aria-hidden="true"` on the decorative check badge so screen readers don't double-announce the checked state.

### PR #214 ... catalog-gap auto-file from the suggest path (Phase F §0a-2 follow-up)

PR #211 shipped the catalog-gap tracker substrate + CLI yesterday. This closes the loop: when the wizard's suggest path can't satisfy an interview's intent_tags, a gap is auto-filed so tier-2 prioritization becomes signal-driven.

- **`capability-suggest.ts`** ... new `findUnmatchedTags({ interview_tags, capabilities }) → string[]`. Pure function. Case-insensitive matching, deduped, sorted (case-insensitive `localeCompare`) for deterministic gap ids. Original interview-side casing preserved in the output so the gap entry reads as the operator wrote it.
- **`catalog-gap.ts`** ... new `if_exists?: 'fail' | 'skip'` option on `recordCatalogGap`. Default `'fail'` preserves the CLI semantic (manual filings raise on collision). Auto-file paths pass `'skip'` and get the existing record back unchanged, so operator-edited fields (status, resolution_note) survive the auto-call.
- **`session.ts`** ... `suggestCapabilitiesFromTranscript` moved from a module-level helper to a method on `OnboardingSession` (needed `this.nowFn`). New `fileCatalogGapForUnmatchedTags`:
  - ID via `slugifyGapId('onboarding ' + sorted_tags.join(' '))` ... same orphan set across sessions → same id → `if_exists: 'skip'` short-circuits.
  - Description: *"Onboarding interview produced no Capability match for intent_tag(s): <list>. Consider adding a Capability that handles <it/them>."*
  - `context: 'onboarding'`, `related_intent_tags: <sorted>`.
  - Errors logged + swallowed; the suggest path always returns its actual suggestions. Gap-recording must never break onboarding.

Trigger fires when `unmatched_tags.length > 0`, which covers both the total-miss case AND the partial-miss case (some Capabilities matched, but some tags went orphan). The richer-signal partial case was the right scope ... per-tag-set granularity feeds tier-2 review without dropping the broader "no match at all" case.

Tests: 8 new on `findUnmatchedTags`, 2 new on `recordCatalogGap`'s `if_exists`, 3 new on `OnboardingSession`'s auto-file path (filed on unsatisfied suggest, no double-file on repeat with same orphan set, no gap when transcript has zero intent_tags). `pnpm verify` clean (1754 tests).

The session uses the existing `_2200_GAPS_DIR` env override for tests (same pattern as `_2200_CATALOG_DIR`); no new constructor parameters needed.
