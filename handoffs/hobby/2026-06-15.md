Doug said "I need to be able to run this from scratch and have it all work ...

**Found a real installer bug.** Running the one-line installer over headless SSH
aborted right before setup:

```
> Setting up 2200...
/tmp/2200-install.sh: 482: cannot open /dev/tty: No such device or address
✗ Setup did not complete.
```

`install.sh` tested `[ -r /dev/tty ]` to decide whether to reattach the terminal
for setup's one interactive question. The device node passes the `-r` permission
test even with **no controlling terminal** (headless SSH, CI, cron), but `open()`
then returns ENXIO, killing the install. My first fix (`{ : < /dev/tty; }`) made it
worse under dash: a redirection error on a POSIX **special built-in** (`:`/`exec`)
force-exits a non-interactive shell, *uncatchable* by `if`/`||` — that's why a bash
`sh -n` passed but Ubuntu's dash died with status 2. Final fix probes the open in a
**subshell** `(exec < /dev/tty)` so the force-exit is contained and we fall back to
a fully non-interactive `2200 setup`. (PR #285.)

### `2026.615.1301` ... the web app is now actually served

**The bug Doug hit:** after install + `2200 web` (or the URL setup prints), the
browser showed *"The web app has not been built yet"* with only the bare API up.

**Root cause:** the published npm package never contained the built web UI.
`package.json#files` ships `dist/`, but the web app builds to `apps/web/dist` and
was never copied in. `tsup` runs `clean: true`, so anything staged into `dist/`
before the build is wiped. And `resolveStaticDir` only looked for `apps/web/dist`,
which isn't in the package at all.

**Fix (PR #284, merged, released, live on npm):**
- `scripts/bundle-web.mjs` copies `apps/web/dist` → `dist/web` *after* the build,
  wired into `prepack` via a new `bundle:web` script. Every pack/publish now
  carries the web app.
- `resolveStaticDir` walks up from the server module checking `dist/web` (prod)
  then `apps/web/dist` (dev), so it resolves no matter which bundle the server
  code was inlined into.
- eslint ignores `scripts/**` (plain Node `.mjs`, outside the TS project).

**Verified live from npm** (not just the local tarball): a fresh
`npm install -g @twentytwohundred/2200-cli@2026.615.1301` in a clean container,
then `2200 setup`, serves the real app (`<title>2200</title>` + hashed JS/CSS),
`staticDir` bound to `.../dist/web`. `pnpm verify:all` green (2137 + 95).

**My miss:** earlier setup verification only checked the API returned HTTP 200;
I never loaded the app HTML, so the missing static dir slipped through. Setup
verification now asserts on served app content, not just API health.
