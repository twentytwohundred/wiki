### #110 — cleanup: split unused-import-leaking modules

Four rollup warnings had been firing on every `pnpm build`:

```
"createServer" is imported from external module "net" but never used in "dist/runtime/agent/bootstrap.js".
"generateKeyPairSync" is imported from external module "crypto" but never used in "dist/runtime/agent/bootstrap.js".
"createConnection" is imported from external module "net" but never used in "dist/runtime/supervisor/bootstrap.js".
"stat" is imported from external module "fs/promises" but never used in "dist/runtime/supervisor/bootstrap.js".
```

Tsup tree-shakes the consumer of an import but leaves the import declaration in the bundle when both halves of a file are reachable but only one half is actually used. Three modules were the offenders: `transport-uds.ts`, `keystore.ts`, `pub/keypair.ts`. Each had a producer-side function (listenUds / generateAgentKeypairs / generateKeypair) only used by the supervisor, plus a consumer-side function (connectUds / loadOrCreateMasterKey / signMessage etc.) used by the agent and CLI. The agent bundle pulled in the file, tree-shook out the unused half, but couldn't drop the import declaration.

Fix: split each file along its producer/consumer boundary so each entry's bundle imports only what it uses.

- `transport-uds.ts` ... `uds-connection.ts` (shared) + `uds-server.ts` (listen) + `uds-client.ts` (connect). Old file deleted; 19 callers updated.
- `keystore.ts` ... extracted `keystore-keygen.ts` with `generateAgentKeypairs`.
- `pub/keypair.ts` ... extracted `keypair-generate.ts` with `generateKeypair`.

`pnpm build` is now warning-free. Pure refactor, no behavior change.

### #111 — Pulse runtime emitter (v0.2 substrate)

[[pulse]] has been a locked design with no runtime backing. The only writer was the detector-trip path in Epic 2, which meant the dot was effectively binary (alive vs redlined). This PR gives every Agent a continuously-updating activity signal so the design's color gradient is actually meaningful. UI epics 15 / 16 will consume `<agent>/pulse.json`; the runtime now produces it correctly.

**Schema bump** (additive, with v1 migration):

- v1 (Epic 2 trip handler) had three states: `green | yellow | redlined`.
- v2 (this PR) is the full design palette: `resting | working_light | working_medium | working_hard | redlined | stopped`, plus a numeric `intensity` in `[0, 1]` so the UI can smooth between bands without re-querying.
- `src/runtime/agent/pulse/reader.ts` migrates v1 to v2 in-memory; new writes are always v2.

**Activity model:**

- Sliding 60s window of cost-bearing events (`model_call_end` weighted by `cost_usd`; `tool_call_end` at $0.005 each as a placeholder until tools have first-class cost).
- `intensity = sum(weights) / target` where target defaults to $0.10/min. A redlined Agent is one spending $0.10/min sustained.
- Bands with hysteresis: upward transitions immediate; downward require 2s dwell so brief spikes do not jitter the dot.
- `setTrip(kind, id)` pins to redlined synchronously with the trip-record write; `clearTrip()` snaps back to whatever intensity says (trip clear is a discrete event, no dwell).

**Wiring:**

- `AgentLoop.pushEvent` forwards every `LoopEvent` to the emitter via `record(event)`.
- `AgentLoop.tripped()` calls `setTrip()` so the dot pins synchronously with the trip record being persisted.
- `AgentProcess` instantiates and starts the emitter alongside the loop; stops it on shutdown (writes `state: 'stopped'` as the final record).
- `trip-record.ts` updated to write v2 shape directly (`intensity: 1` on trip; `intensity: 0` on `resetPulseToGreen`, which now writes `state: 'resting'`).

**Tick cadence:** 250 ms (4 Hz), per the spec's "high-frequency state for smooth UI" requirement.

### #112 — Epic 8 Phase C: cross-Agent brain reads with permission

Phase A landed per-Agent brains (PR #71-#74). Phase B landed the shared brain (PR #99). Phase C closes the cross-Agent question: an Agent that wants to know what another Agent has been thinking can now ask, and the owner controls who gets to.

**Permission store:**

- `<home>/state/brain/<owner>/permissions.json` ... schema-versioned, sorted + deduped reader list, mode 0600.
- `readBrainPermissions / writeBrainPermissions / grantBrainRead / revokeBrainRead / canReadBrain`.
- `BrainPermissionDeniedError` includes the exact CLI to grant access in its message ... a denied caller gets unstuck without docs.

**Read-only DB access:**

- `BrainIndex.openReadOnlyAtPath` uses better-sqlite3's `{ readonly: true, fileMustExist: true }`. SQLite supports concurrent readers + a single writer, so the owner Agent's writer is unaffected. The reader closes the handle as soon as the query completes.
- `BrainIndexNotFoundError` for the case where the target Agent has never written a note. Cross-Agent search returns an empty hits array rather than throwing.

**New baseline tools:**

- `brain.search_agent({ agent, query, limit, types?, any_tag? })` ... permission-checked FTS5 search across another Agent's brain. Self-search routes through the warm registry handle.
- `brain.list_agent({ agent, type?, tag?, limit })` ... permission-checked enumeration.
- Both throw `BrainPermissionDeniedError` when the caller is not in the target's readers list. An Agent can always read its own brain.
- Baseline tool count goes 20 → 22.

**CLI:**

- `2200 brain permissions <agent> [--add reader] [--remove reader]` (no flags = list).
