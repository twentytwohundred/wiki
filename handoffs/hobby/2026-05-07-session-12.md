## Bug-of-the-day chain (Simon → Grok)

Worth reading because the chain teaches a lesson about what "model identity" really is.

1. Doug used the new picker to switch Simon from DeepSeek to xAI/Grok 4.3.
2. Simon failed every chat with `Incorrect API key provided: sk***2e`. Root cause: Simon's identity still had `provider_secret: { source: env, id: DEEPSEEK_API_KEY }` from his prior provider — the runtime obediently shipped the DeepSeek key (which uses `sk-` prefix) to xAI's endpoint, which rejected it. Fix: #160 strips that block on provider change. Hand-cleaned Simon's live identity + restarted the daemon (which had been started before `XAI_API_KEY` was added to runtime.env, so the supervisor didn't have it in its env either).
3. After the fix Simon was running on Grok and chat worked. Doug asked "what model are you?" and Simon answered `anthropic/claude-haiku-4-5`. Root cause: Simon's persona body had a `## Default model: anthropic/claude-haiku-4-5` block left over from his Haiku days, so Grok read its persona and parroted the prose. Fix: #161 deletes the section from both live identities and the seed templates.
4. Simon then admitted (correctly) that he had no way to introspect his actual runtime model. Real fix: #162 prepends a `## Runtime` block to the system prompt naming the Agent and quoting `<provider>/<model_id>` from the active frontmatter. Regenerated every task, so future operator switches don't drift.

The pattern: **anything provider-specific in an Identity is a drift hazard.** The frontmatter is canonical; persona prose lying about the model is worse than persona prose being silent on the model. Future epic-9 onboarding should keep that in mind — never bake a hard-coded model claim into a persona body.

## Decisions made (no separate ADR yet)

- **`local` provider is OpenAI-compatible only at v1.** Reads `LOCAL_BASE_URL` from env (default `http://localhost:11434/v1` = Ollama). API key optional; `LOCAL_API_KEY` defaults to `"ollama"` when unset. Editing the URL goes through `PUT /api/v1/settings/providers/local/url`. No special-case Anthropic-style adapter for local.
- **Provider keys live in `~/.config/2200/runtime.env`.** Web writes are upserts that preserve comments and unrelated lines (mode 0600, parent dir 0700). Power users editing the file by hand keep working. The supervisor reads runtime.env once at boot, so adding/changing a key requires `2200 daemon restart` to take effect — surfaced via `restart_required: true` in every PUT response.
- **`provider_secret` and `followup_model_id` are provider-coupled.** A model switch via the picker drops both unless the caller explicitly supplies a new follow-up id. Hand-edited identities can still set them; the auto-clear only fires on the rewrite path.
- **Model id regex now allows dots** (`^[a-z0-9.-]+$`). Real model ids contain dots (`gemini-2.5-pro`, `grok-4.3`); the pricing catalog already used dotted keys; the schema now matches.
- **Chat-spawned tasks default to hidden** in RECENT TASKS. The chat screen surfaces them already; doubling them up clutters the panel. `?include=all` opt-in for power users.
