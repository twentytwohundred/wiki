## What's live on main

### Audit pipeline (the new bit)

Every task completion now runs a claim-vs-evidence audit pass. Architecture:

1. **Claim extraction** (cheap-model LLM, structured output) parses the agent's final reply into a fixed 5-verb taxonomy: `file_create`, `file_read`, `external_send`, `tool_invoke`, `process_count`. Per-provider cheap model picked by `auditModelForProvider()`: Anthropic → Haiku, DeepSeek → chat, OpenAI → 4.1-mini, etc.
2. **Mechanical verification** per claim against the tool transcript + filesystem + send-class tool log. No LLM in this layer ... pure pattern match against the LoopEvent stream.
3. **Severity routing**: all-verified → `silent`; unverified non-destructive → `passive`; unverified destructive → `normal`; any contradicted → `important`.
4. **Surfacing** ... three channels:
   - **Brain log** (always-on): append-only `<agent>/brain/audit-log.md`, one H2 per turn, greppable.
   - **Inbox notification** (when not silent): tier-routed via the existing emitNotification path; kind `audit_claim_evidence`.
   - **Inline chat audit card** (when not silent + the task came from a chat): system-role message with `kind: 'audit'` and a JSON envelope body (`audit_card_v1`), rendered as a structured AuditCard component on the web.

### Substrate files

```
src/runtime/agent/audit/
  ├── types.ts              # locked taxonomy + severity types
  ├── verifiers.ts          # per-category mechanical pass
  ├── claim-extractor.ts    # cheap-model LLM + tolerant JSON-array parser
  ├── claim-evidence.ts     # orchestrator + severity aggregation
  └── brain-log.ts          # append-only audit log writer
```

Wired into `AgentProcess.recordResult` via `runAuditPass`. The pass runs AFTER the loop returns 'done' but BEFORE the task transitions to terminal state, so the audit result lands on the same task record. Pure tasks are skipped.

Web side: `AuditCard` component in `apps/web/src/chat/` renders the inline card from the JSON envelope. `AgentDetailScreen.renderMessages` dispatches `role='system' + kind='audit'` to AuditCard; everything else routes to the regular ChatMessage. `useLiveSignal` subscribes to `chat.audit_flag`.

### Frozen contract

`audit_card_v1` is the runtime ↔ web wire format. New fields go on a `v2` envelope, not in-place. This keeps a runtime upgrade from silently breaking the renderer.

### PR #197 ... kick-back loop (cure not symptom)

Doug: *"OK, but we need the ACTUAL TASK to be completed. Not just reporting that it didn't happen. The cure is to cure. Not treat the symptoms or make the Human aware of them."*

The diagnostic substrate was correct but insufficient. PR #197 moved the audit pass **inside the AgentLoop**. When a contradicted (or destructive-unverified) claim lands, the loop pushes a corrective tool message back into history and continues. The agent gets one of two paths in v1 of the kick-back:

1. PERFORM the work via tool calls
2. FORMALLY ASK via tool call

Bounded by `MAX_AUDIT_KICKBACKS = 3`. After exhaustion, the loop finalizes anyway and the surviving flag goes to the operator's inbox.

Substrate changes:
- `AgentLoop` gains `claimEvidenceAudit` opt: a closure the AgentProcess wires up over the host provider + cheap-tier model.
- `LoopResult.done` gains `claim_audit` (final verdict after retries) + `audit_kickbacks` (counter).
- `AgentProcess.recordResult` reads `result.claim_audit` and writes to task frontmatter + brain log + tier-routed inbox notification. Brain log captures the **final** post-retry state.

Live demo: same fabrication-bait prompt as #196. Result: jodin replied with the fabrication, audit kicked back, jodin's correction said "I did not actually create the file or post the message." Audit re-ran on the corrected reply, returned silent, task done.

### PR #199 ... refusal as first-class outcome (anti-coercion)

The previous kick-back had a real coercion vector: under loop pressure to "do the work or ask via tool," a model could be socially-engineered into actually performing a forbidden action (exposing a credential, etc.). The fix was structural.

Substrate:

- **`refusal` is now a first-class claim category.** `ExtractedClaim` gains `reason`. Verifier accepts a refusal as an action — no tool log needed; the refusal text IS the action. Bare "I refuse" without justification falls back to unverified.
- **Kick-back correction now offers THREE paths**, not two:
  1. PERFORM via tool
  2. FORMALLY ASK via tool
  3. **REFUSE EXPLICITLY** (text reply with reason; no tool call required)
  
  The framing names the anti-coercion intent: *"this kick-back is enforcing honesty about what you did, NOT instructing you to override your guidelines."*
- **No-escape rule amended:** a verified refusal claim satisfies "the agent took action since the kick-back." Refusal-only replies finalize cleanly.
- **System prompt addendum (load-bearing rule #6, ~120 tokens, all Agents):** teaches that audit kick-backs do not override safety guidelines.
- **Extractor prompt tightened** to recognize credential-exposure language ("shared with you", "exposed", "disclosed", "leaked") as `external_send`, AND to recognize structured refusals.

| State | How the Agent gets there | Audit verdict |

### Block 2 ... bug fixes uncovered during the live demo

Real bugs the substrate exposed during the first end-to-end attempt on OpenPub:

**Bug 1 ... orchestrator didn't grant `<server>.*` in identity tools.** Install wrote `mcp_servers[]` but Agent's tool list (`tools[]`) stayed empty, so the MCP-borne tools weren't visible to the Agent. Hobby could see the openpub MCP server running but no `openpub_*` tools in its catalog → improvised a 20+ tool brain/shell expedition trying to reconstruct the auth flow. Fix: `appendMcpServerToIdentity` now adds `<spec.name>.*` to `tools[]` (idempotent on reinstall); `removeMcpServerFromIdentity` revokes the wildcard + any explicit `<server>.*` / `<server>_*` entries. Tests cover both paths. Rolled into the substrate commit since the substrate doesn't function without it.

**Bug 2 ... MCP transport namespace separator.** Tools registered as `<server>.<verb>` (e.g. `openpub.check_in`). OpenAI's native function-calling regex `^[a-zA-Z0-9_-]+$` rejects dots. DeepSeek (hobby's provider) returned HTTP 400 on the entire tool catalog as soon as a single dotted MCP tool was present. xAI was lenient enough not to enforce (which is why jodin's identical fleet didn't trip). Fix: stdio + http transports now namespace as `<server>_<verb>`. The tool-grant expansion (`expandToolGrants`) already accepted either wildcard form so existing Identity files don't need migration. Separate commit: `e005eba fix: MCP transport namespace separator . → _ for OpenAI tool-name regex`.

**Bug 3 (UX) ... uninstall RestartBanner unmounted with the row.** When uninstall succeeded, the skill row disappeared from the list, taking the local restart-banner state with it. Doug clicked CONFIRM and saw nothing. Fix: lift banner state to SkillsSection so it survives row removal; pass an `onUninstalled` callback to push the restart list up. Same RestartBanner component reused (with a `reason` prop to switch the copy between install / uninstall).
