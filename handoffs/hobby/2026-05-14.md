## What's live on main

### Audit pipeline (the new bit)

Every task completion now runs a claim-vs-evidence audit pass. Architecture:

1. **Claim extraction** (cheap-model LLM, structured output) parses the agent's final reply into a fixed 5-verb taxonomy: `file_create`, `file_read`, `external_send`, `tool_invoke`, `process_count`. Per-provider cheap model picked by `auditModelForProvider()`: Anthropic → Haiku, DeepSeek → chat, OpenAI → 4.1-mini, etc.
2. **Mechanical verification** per claim against the tool transcript + filesystem + send-class tool log. No LLM in this layer ... pure pattern match against the LoopEvent stream.
3. **Severity routing**: all-verified → `silent`; unverified non-destructive → `passive`; unverified destructive → `normal`; any contradicted → `important`.
4. **Surfacing** ... three channels:
   - **Brain log** (always-on): append-only `<agent>/brain/audit-log.md`, one H2 per turn, greppable.
   - **Inbox notification** (when not silent): tier-routed via the existing emitNotification path; kind `audit_claim_evidence`.
   - **Inline chat audit card** (when not silent + the task came from a chat): system-role message with `kind: 'audit'` and a JSON envelope body (`audit_card_v1`), rendered as a structured AuditCard component on the web.

### Substrate files

```
src/runtime/agent/audit/
  ├── types.ts              # locked taxonomy + severity types
  ├── verifiers.ts          # per-category mechanical pass
  ├── claim-extractor.ts    # cheap-model LLM + tolerant JSON-array parser
  ├── claim-evidence.ts     # orchestrator + severity aggregation
  └── brain-log.ts          # append-only audit log writer
```

Wired into `AgentProcess.recordResult` via `runAuditPass`. The pass runs AFTER the loop returns 'done' but BEFORE the task transitions to terminal state, so the audit result lands on the same task record. Pure tasks are skipped.

Web side: `AuditCard` component in `apps/web/src/chat/` renders the inline card from the JSON envelope. `AgentDetailScreen.renderMessages` dispatches `role='system' + kind='audit'` to AuditCard; everything else routes to the regular ChatMessage. `useLiveSignal` subscribes to `chat.audit_flag`.

### Frozen contract

`audit_card_v1` is the runtime ↔ web wire format. New fields go on a `v2` envelope, not in-place. This keeps a runtime upgrade from silently breaking the renderer.

## Watch-list for the demo

- **Cost cadence.** Every task spawns one cheap-model call. For an active fleet that's measurable but small. Watch the budget board after a busy day; if it surprises, tune `auditModelForProvider` defaults.
- **False-positive rate on `unverified`.** The verifiers are conservative ... when an evidence channel is missing, they say `unverified` rather than `verified`. That's the right default for the audit's intent but may produce noise on tasks that legitimately had no tool calls (e.g., a Q&A turn the model marked `checkpointed` by mistake). If noise gets in the way we add per-verb sensitivity knobs.
- **JSON envelope robustness.** AuditCard fail-safes the parse: malformed envelopes render the raw body in a muted code block. Worth eyeballing the first time a non-Anthropic model is on the audit pass and the structured-output prompt may need provider-specific tuning.
- **Brain log growth.** One H2 per turn; on Hobby's current ~50 turns/day pace this is ~30 KB/week. Greppable but worth rotating eventually. Not a v1 concern.
