## Focused review pass (mid-day) ... and the fix-up PR

End-of-morning review of all code that landed today surfaced two real bugs, one piece of dead code, and several friction points. The four most important items got fixed in **PR #89 (review-fixes)** the same morning. Items still open are documented at the bottom for follow-up.

### Fixed in PR #89

**1. ✅ Spawn CLI: daemon-running guard moved to top of action.** Operators get the stop-the-daemon hint immediately rather than after sitting through a 5–10 minute interview + LLM summary call.

**2. ✅ AgentProcess MCP-spawn loop: try/catch with cleanup.** Managers now push to `this.mcpManagers` BEFORE awaiting `start()` so a partial failure cleans up successfully-started managers (in reverse order, best-effort) before rethrowing. No more leaked child processes when, say, the third-of-five MCP server fails at boot.

**3. ✅ Spawn CLI dead code deleted** (`handoff.frontmatter.identity = { ...handoff.frontmatter.identity }` no-op spread).

**4. ✅ mcp_servers auto-applied to the Identity.** The bigger structural fix:
- `HandoffFrontmatter` gains an optional `mcp_servers` field (additive; v1 docs without the field still validate via the Zod default of empty array).
- `buildIdentityFromHandoff` (Epic 5) passes mcp_servers through and seeds one wildcard tool grant per declared server (`github.*`) so the Agent has tool access at start time.
- `buildHandoffFromTranscript` (Epic 14) accepts an optional `mcpServers` arg.
- The spawn CLI passes the suggested-tools list to the handoff builder.

The operator no longer copy-pastes YAML post-spawn; the Identity is written with mcp_servers populated, ready to start once the env vars are set.

### Friction / design holes still open (no immediate fix needed)

**5. Restart manager does not refresh the tool list on restart.** Documented in the module comment. If an operator pins a newer MCP server version that exposes a new tool, the Agent never sees the new tool without a full Agent restart. Phase A acceptable; flag for Phase C polish.

**6. Migration orchestrator double-opens BrainStore + BrainIndex.** [`src/runtime/migration/orchestrator.ts:166-184` then `192-211`]. Once for inline notes, once for the continuity note. Wasteful but harmless; minor.

**7. AgentProcess inherited env is conservative** (`PATH`, `HOME`, `USER`, `LANG`). Operators with MCP servers needing additional env vars (`XDG_CONFIG_HOME`, `LC_ALL`, `NODE_OPTIONS`, etc.) specify them via Identity. Fine; document if it surprises someone.

**8. Onboarding `expects` field declared but not enforced.** Question schema admits `expects: yes_no | name | email | cron | time | free_form` but the runtime ignores it (free-form everywhere). Documented as "advisory at v1." Future polish.

**9. Onboarding tool-suggestions ops branch uses substring match for "slack".** Mixes pattern matching into the otherwise-curated table. Predictability suffers slightly; minor.
