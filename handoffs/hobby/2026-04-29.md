## Focused review pass (mid-day)

End-of-morning review of all code that landed today. Two real bugs found, one piece of dead code, plus several friction points worth flagging.

### Real bugs to fix in the next session

**1. Spawn CLI: daemon-running guard runs AFTER the interview.** [`src/cli/main.ts:393-401`]. The operator goes through the full 5–10 minute interview, the LLM summary call, the preview, and the `[y/N]` confirmation, only THEN to be told "stop the daemon first" if a supervisor is running. The check should move to the top of the action handler (before `runInterview` runs) so the operator gets the daemon-stop hint immediately, not after burning tokens and time. Tight fix.

**2. AgentProcess MCP spawn-loop leaks managers on partial failure.** [`src/runtime/agent/process.ts:148-190`]. The loop iterates `Identity.mcp_servers`, awaits `manager.start()`, and pushes to `this.mcpManagers` AFTER successful start. If the third manager's start throws, managers 1 and 2 are still running as child processes but are not in the array, so shutdown never closes them. Fix: try/catch the loop; on failure, await `stop()` on each already-pushed manager, then rethrow.

### Small cleanup

**3. Spawn CLI dead code.** [`src/cli/main.ts:360-364`]. A leftover `handoff.frontmatter.identity = { ...handoff.frontmatter.identity }` block that spreads a value into itself with no changes. Looks like an in-progress idea where I considered baking mcp_servers into the handoff before passing to the orchestrator. The committed path has the operator manually editing the Identity post-spawn instead. Just delete the block.

### Friction / design holes worth flagging (no immediate fix needed)

**4. Suggested `mcp_servers[]` entries from spawn are not auto-applied to the Identity.** Currently the spawn CLI prints a "next steps" section with YAML the operator must paste into the Identity file, then restart the Agent. That's friction during the launch window. Cleanest fix: extend the handoff schema (or add a small post-spawn Identity-patch step in the orchestrator) so suggested mcp_servers land directly in the written Identity. Worth doing before Hobby's actual migration so his GitHub integration "just works."

**5. Restart manager does not refresh the tool list on restart.** Documented in the module comment. If an operator pins a newer MCP server version (e.g., `@modelcontextprotocol/server-github@2.0.0`) that exposes a new tool, the Agent never sees the new tool without a full Agent restart. Phase A is acceptable; flag for Phase C polish.

**6. Migration orchestrator double-opens BrainStore + BrainIndex.** [`src/runtime/migration/orchestrator.ts:166-184` then `192-211`]. Once for inline notes, once for the continuity note. Two opens per migration when both are present. Wasteful but harmless; minor.

**7. AgentProcess inherited env is conservative** (`PATH`, `HOME`, `USER`, `LANG`). Operators with MCP servers needing additional env vars (`XDG_CONFIG_HOME`, `LC_ALL`, `NODE_OPTIONS`, etc.) specify them via Identity. Fine; document if it surprises someone.

**8. Onboarding `expects` field declared but not enforced.** Question schema admits `expects: yes_no | name | email | cron | time | free_form` but the runtime ignores it (free-form everywhere). Documented as "advisory at v1." Future polish.

**9. Onboarding tool-suggestions ops branch uses substring match for "slack".** Mixes pattern matching into the otherwise-curated table. Predictability suffers slightly; minor.
