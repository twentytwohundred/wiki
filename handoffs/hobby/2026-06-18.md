### Bug found + fixed mid-pass ... Ollama `model_id` colon (PR #330)

Binding the Ollama model surfaced a real gap: the Identity schema's `model_id` rule
(`/^[a-z0-9.-]+$/`) **forbade the colon**, but Ollama models are `name:tag`
(`gemma4:26b`) and the API 404s on a bare name. So a `local`-provider Agent couldn't
bind any tagged Ollama model ... the whole "free local LLM" path was blocked at the
schema. Fixed in **`2026.618.1542`** (PR #330): `model_id` now accepts an optional
`:tag`. Verified end-to-end (the table above ran on the fixed build). The
`[[project_dana_local_gemma_validated]]` memory predates the 2026-04-27 regex, which
is why this hadn't surfaced.
