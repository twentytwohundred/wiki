# Locked decisions from this session

- **MCP-native runtime.** Recorded at [[2026-04-25-mcp-native]]. The 2200 runtime speaks MCP as both client and server. No parallel internal tool protocol. Inherits the MCP ecosystem (Shopify's four official servers and others); pays the cost of living within MCP's evolution.

- **Tool baseline + plan/run/perm wrapping.** Recorded at [[2026-04-25-tool-baseline]]. Every Agent gets a baseline tool set by default. Every tool call passes through plan (Agent's stated intent), run (the call), perm (authorization checks). The wrapping is universal; no fast path skips it. Skills add to the baseline; they do not replace it.

- **Skills as first-class object.** Recorded at [[2026-04-25-skills-first-class]]. Skill is its own object alongside Agent/Project/Task/Pub/Notification/Tool/Schedule/Brain. Extensions are higher-level packaging that can include Skills. Epic 11 produces Skill objects, not wrapped Extensions. The earlier [[2026-04-24-skill-compatibility-pipeline]] is not edited — its five-phase pipeline still applies, just with a simpler "register as Skill" install step.

- **Plan/run/perm schemas (v0.1).** Locked. Per-record `schema_version` (each artifact owns its version). Plan: `schema_version, id, ts, agent, task_id, call_id, model, tool, args, precondition, predicted_outcome, reason`. Run: `schema_version, id, ts_start, ts_end, agent, task_id, plan_ref, call_id, tool, inputs, output, output_ref, error, duration_ms, cost_metrics`. Perm: `schema_version, id, ts, agent, task_id, plan_ref, call_id, tool, checks[], authorized, denial_reason`. v1 perm check types: `tool_in_set, extension_scope, cost_behavior_gate, user_pref, idempotency_compatible, command_pattern`. The `model` field on plan was Doug's addition for cross-model drift analysis.

- **`process` tool deferred to Epic 9.** Long-running subprocess management is intentionally not in v1 baseline. The supervisor exists for Agent process management; spawning a parallel surface where Agents launch opaque long-running children would split the model. Future shape (`process.start/read_output/write_input/signal/stop/list` flowing through supervisor RPC) sketched in Epic 2 as best current thinking; Epic 9 owns final design. v1 fallout is deliberate: `shell.run npm run dev` hits the `tool_timeout` detector, which is the right signal.

- **Idempotency model (mechanical perm-layer guard).** Tool-level categories declared at MCP server registration. Task-level categories declared in task frontmatter (default `pure`). Compatibility matrix: pure→pure only, checkpointed→pure+checkpointed, destructive→all. Enforced via `idempotency_compatible` perm check. Mis-categorization fails on the first wrong call, not on auto-resume. Default `pure` is safe because the safety pre-condition is mechanical, not aspirational.

- **`shell.run` tighter permission model.** Beyond standard plan/run/perm, every `shell.run` call passes through a `command_pattern` perm check. First-time-seen commands and configured "always confirm" patterns surface a notification before run fires. Approved patterns can be remembered. Specific patterns can opt the call into safer idempotency categories (e.g., `git status` → pure). The check exists only on `shell.run` because shell is the most-powerful baseline tool; the friction is intentional.

- **Detector behavior aligned with [[2026-04-24-cost-behavior-shape]].** Five detector kinds (`tool_repetition`, `no_progress`, `tool_timeout`, `cost_burst`, `error_storm`) with conservative per-Agent-configurable thresholds. On trip: pause, write Passive notification, set `BLOCKED_ON_DETECTOR`, write detector-trip record to `brain_dir/.records/detector-trips/<id>.md`, update pulse-state file. v1 emits the data; UI epics surface the visible Pulse and the Behavior dashboard layered protections from this same record stream. No parallel response model.
