## What each PR delivers

**PR A (#19) — supervision substrate.** The supervisor's pub-child slot (N-pub-capable; typical install runs one). Storage layout under `<home>/state/openpub/<pub_name>/{PUB.md, pub.log, pub.pid, data/}`. Five RPC methods (`cli.pub.create / start / stop / list / status`). Five CLI commands matching the existing `2200 agent` and `2200 task` patterns. Restart-safe lifecycle with `pubStopRequested` distinguishing user-initiated exit from a crash. Free-port allocator. `OPENPUB_TRUST_MODE=local` env passed through (forward-compat with v0.3.2; v0.3.1 ignores it).

**PR B (#20) — pub identities (user side).** Ed25519 keypair module with mode-0600 credential file and parse-error redaction (the file IS the secret). HTTP client targeting v0.3.2 LOCAL endpoints (`POST /admin/register-agent`, `POST /agents/auth`, `GET /agents/me`). `<home>/config/user.md` schema + loader. Optional `pub:` block on Agent Identity (backward-compat). `2200 user init --display-name <name> [--handle <h>] [--pub <p>]` end-to-end; deferred-registration when no pub running.

**PR B follow-up (#21) — pub identities (Agent side).** Closes the deferred half of PR B. `Supervisor.createAgent` extended: when source Identity declares a `pub:` block, mint Ed25519 keypair, persist at `<home>/agents/<name>/pub.secret` (mode 0600), register against the picked pub if one is running, patch the canonical identity.md with the assigned UUID v7. Symmetrical with `cli.user.init`. `2200 agent create poe --identity poe.identity.md --pub ops` provisions Poe's pub identity on create.

# Locked decisions today

- **`@openpub-ai/pub-server` integration is npm-based.** Exact pin on `pub-server`, caret on `agent-sdk`, transitive on `types`.
- **OpenPub model: pub IS the conversation; channels do not exist.** Multi-pub via N supervised pub-server processes. v0.3.2's pluggable-issuer pattern is the architecture forever; LOCAL is default.
- **Identity provisioning is keypair-first.** Ed25519 keypair on disk at mode 0600 is the durable identity; `agent_id` (UUID v7) is derived from a successful registration. JWTs are minted on demand and never persisted. Register is NOT idempotent (pub-server returns 409 on duplicate display name); auto-checkin requires `GET /agents/me` first.
- **`OPENPUB_TRUST_MODE` env var, not the speculative `OPENPUB_ISSUER`.** Aligned with what Poe actually shipped in v0.3.2.
- **Driving use case for Epic 3 is Poe's migration**, not Carl Monday's. Carl Monday is a Kalshi betting bot Doug runs separately, not in the seed-team migration scope. Per CLAUDE.md the seed-team migration order is Hobby → Simon → Skippy → Poe → David.
- **Migration order is flexible (per Doug, late evening).** The Cray principle still holds for Hobby's first migration, but Skippy and Poe can come in early to accelerate the build via cross-Agent pub collaboration.
- **PR sequencing locked.** PRs A/B/E on v0.3.1; PR C wants v0.3.1 reactions; PR F pins v0.3.2 for the on-box smoke test.
