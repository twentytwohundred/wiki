### #106 — Epic 9 Phase B-2: OAuth flows

Browser-based Authorization Code + PKCE flow for built-in providers (google, github, slack). One-shot `127.0.0.1` redirect server with ephemeral port + state-nonce + PKCE S256 verifier. Provider-agnostic flow runner; provider configs live in a registry.

- `src/runtime/oauth/types.ts`: `OAuthProviderConfig`, `OAuthTokenResponse`, `OAuthError` taxonomy (7 codes).
- `src/runtime/oauth/pkce.ts`: RFC 7636 PKCE pair + state nonce.
- `src/runtime/oauth/providers.ts`: registry + `readClientCredentials(name)` from `_2200_OAUTH_<PROVIDER>_CLIENT_ID/SECRET` env vars (kept off disk).
- `src/runtime/oauth/redirect-server.ts`: one-shot listener; success / error pages; timeout + abort.
- `src/runtime/oauth/flow.ts`: end-to-end runner; injectable fetch + browser opener; decoupled from the vault so it stays unit-testable.
- CLI: `2200 oauth providers / login / status / revoke`.

`oauth login` initially wrote a single vault entry that held the refresh_token (or access_token if no refresh was returned). PR #107 reworked that to write two separate entries (see below).

### #107 — Epic 9 Phase B-3: token refresh

Background service in the supervisor that ticks every 60s and refreshes any vault entry expiring within 5 min. Fixes the "single entry holds refresh_token but the consumer needs the access_token" mismatch by splitting storage.

- Storage shape (BREAKING since Phase B-2 was hours old): `oauth login` now writes `<name>` (access + expires_at) AND `<name>-refresh` (refresh_token) as two vault entries. SecretRef consumers lift `<name>` directly with no per-spawn round-trip.
- `src/runtime/oauth/refresh.ts`: pure `refreshAccessToken(provider, refreshToken, clientId, clientSecret, fetchImpl?)` ... POST `grant_type=refresh_token`, validate response, surface OAuthError taxonomy.
- `src/runtime/oauth/refresh-service.ts`: `TokenRefreshService` class. Scans `<home>/agents/<name>/`, lists each vault, refreshes within window, rotates refresh_tokens when the provider rotates, applies per-credential failure cooldown (60s), skips quietly on missing client creds / unknown provider / no companion / malformed expires_at / outside-window.
- Wired into `Supervisor.start` / `shutdown` alongside `Scheduler`.
- New CLI: `2200 oauth refresh <agent> <name>`.
- `oauth status` filters out `-refresh` entries; tags pairs with `[+refresh]`.
- `oauth revoke` deletes both halves.

The original epic spec called for "background job per Agent, runs through the scheduler." Built one supervisor service instead because the unit of work is across-Agent and supervisor-owned. Updated the Epic 9 spec to reflect this deviation.

### #108 — Epic 9 Phase C-1: HTTP MCP transport

Streamable HTTP MCP transport alongside stdio. Identity schema admits both via a discriminatedUnion on `transport` (no schema bump; existing stdio identities unchanged).

- Identity schema: `transport: 'http'` with `url` (URL), `auth: { type: 'none' } | { type: 'bearer', token: SecretRef }`, optional `headers`.
- `src/runtime/mcp/http-transport.ts`: `spawnHttpMcpServer` wraps `StreamableHTTPClientTransport`. Same 2200 facade as stdio (initialize, list tools, namespace as `<name>.<verb>`, forward calls). Bearer token (resolved from SecretRef) becomes `Authorization: Bearer <token>` per request.
- `src/runtime/agent/process.ts`: dispatches on `spec.transport`. stdio uses existing `McpServerManager` (unchanged). HTTP uses `spawnHttpMcpServer`, registers handle in `mcpHttpHandles`, closes in shutdown.
- Tests: end-to-end against the SDK's own `StreamableHTTPServerTransport` mounted on a Node http server. 5 tests cover dispatch, bearer header, 401 rejection, namespacing, static headers.

No restart-manager wrapping for HTTP at v1 (the SDK handles transient errors + SSE reconnection internally; Phase C-2 tool-health surfaces long outages as failure rate).

### #109 — Epic 9 Phase C-2: per-Agent tool health

Aggregates the run records the dispatcher already writes into per-tool stats. Surfaces dormant + failing tools in `2200 agent status` and a dedicated `2200 agent tool-health` command.

- `src/runtime/tools/health.ts`: `aggregateToolHealth(brainDir, agent, opts?)` walks `<brain>/.records/run/**.md`, groups by tool, computes total / ok / error counts, last_called_at, last_error_at, recent_failure_rate (over a window), mean_duration_ms, dormant flag. Tolerates torn / malformed records.
- `renderToolHealthMd(summary)` ... three sections (Failing / Dormant / All), diff-stable.
- Defaults: dormant > 30 days, recent-failure window 20 calls, failing if rate > 25% with >= 4 recent calls.
- CLI: `2200 agent tool-health <name> [--write] [--dormant-days N] [--window N]`. `2200 agent status <name>` prints a one-line summary when records exist.

## Notes for future-me

- The supervisor now has TWO background services: `Scheduler` and `TokenRefreshService`. If a third lands, factor a small `BackgroundService` interface and have Supervisor manage them as a list.
- The HTTP transport casts `transport as unknown as Parameters<Client['connect']>[0]` because the SDK's transport type and our `exactOptionalPropertyTypes: true` tsconfig disagree on `sessionId` narrowing. Local + well-isolated; not a runtime concern. If the SDK tightens this, drop the cast.
- The credential vault is per-Agent salt + per-instance master key (HKDF). The refresh service lives in the supervisor, which has access to all Agent vaults via the master key. Not a security regression; just note that the supervisor process is the trust boundary for vault content.
