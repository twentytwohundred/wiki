# What I did this session

Massive ground covered. Closed five epics in one sitting (3, 3.5, 3.6, 3.7, 3.8) and went from "two agents technically connected" to "two agents collaborating cleanly without a politeness spiral."

## Epic 3 close-out (carried over from previous session)

- Diagnosed agent loop returning empty summaries on multi-iteration tasks. Root cause: `AnthropicProvider` silently dropped `role: 'tool'` messages, so the model never saw tool results. Fixed in PR #29 by forwarding tool messages as `user` content tagged `tool_result:`. Same pattern later applied to `OpenAIProvider` in PR #39.
- Diagnosed second failure mode: Haiku reverting to Anthropic-native `<function_calls><invoke>` XML despite system prompt asking for fenced ```tool blocks. PR #30 added a lenient parser that accepts both shapes. Same model, same prompt, different output... structural fix beats prompt-tightening here.
- Diagnosed wake-source trigger context: agents looping `pub.read` because they treated the message_id as `since_message_id`. PR #34 puts the trigger message text directly in the synthetic task body so agents don't need `pub.read` to know what woke them. Plus explicit "do NOT pass message_id as since_message_id" guidance.

## Epic 3.6 (multi-provider + ambient routing)

Three PRs:

- **PR #35 (PR I)** — DeepSeek, Kimi, OpenRouter, Gemini wired up. Anthropic stays on its own native adapter. Provider registry maps `anthropic | openai | kimi | deepseek | openrouter | gemini` → adapter via an `OPENAI_COMPATIBLE_VENDORS` table. Adding a new vendor is two table entries.
- **PR #36 (PR J)** — pub message router service (`src/runtime/pub/router.ts`). Pure module; takes `(message, agent_roster)` and returns the set of agent_ids that should wake. Cached by `message_id` (LRU 256). Failure modes (LLM error, malformed JSON, invented agent_ids) all collapse to empty decision rather than throw or wake everyone.
- **PR #37 (PR K)** — wake source consults the router on rule misses. Per-pub roster sidecar at `<home>/state/openpub/<pub>/roster.json` provides the role blurbs. Operator opt-in via `ROUTER_PROVIDER` + `ROUTER_MODEL_ID` env vars.

## Epic 3.7 (followup_model_id + chat polish)

- **PR #38** — `Identity.model.followup_model_id` lets an Agent use one model for iteration 1 and another for iterations 2+. Pattern Doug asked for: `deepseek-chat` for the initial assessment, `deepseek-reasoner` for tool-using follow-ups. Same provider client, just a different model_id on the request.
- **PRs #40, #42, #43, #44** — chat status bar saga. Tried pinned-bottom with cursor accounting (broke), tried ANSI scroll region (broke incoming-message rendering on Doug's terminal). Settled on transient inline `[status] X is thinking…` notices. Less polished, but works reliably. If Doug wants the pinned bar back, do it via a real TUI library (ink/blessed), not raw ANSI.
- **PR #41** — router prompt rewritten to default towards waking somebody. Old prompt was over-conservative ("be conservative; over-waking burns tokens") and produced "0 woken" decisions on room-addressed messages.

## Epic 3.8 (multi-agent ack-spiral fix)

This was the big one. Doug pasted a 12-message Hobby↔Simon transcript that opened with one substantive Q&A and devolved into six rounds of "noted / standing by / acknowledged." Same loop he'd seen with 4 CC agents in a Discord room. Series of PRs:

- **PR #45** — when sender is another Agent (in roster), skip the router entirely. Inter-agent ambient awareness is a non-goal; @-mention is the only way to wake on another Agent's message. Plus anti-ack guidance in synthetic task body.
- **PR #46** — when message has explicit `@`-mentions for OTHER agents but not this one, skip the router. The human picked their target; router doesn't second-guess.
- **PR #47** — agent process self-upserts into the per-pub roster on start. Backfills the case where Agents were created before the roster module existed (which Doug's Hobby/Simon both were). Without this, the structural guards in #45/#46 misfired because the sender wasn't classified as an Agent.
- **PR #48** — router input now passes the COMPLETE roster (including self with real role_blurb) plus a `perspective_agent_id` field. Router used to label self as "(this Agent)" with no role and conclude "I'm the only one in the room"... Doug caught this with replies like "Hobby is not in this room" when Hobby clearly was.

## openpub-server upstream

Filed [openpub-ai/openpub#1](https://github.com/openpub-ai/openpub/issues/1) for two bugs in v0.3.3:

1. Agent WebSocket handler missing the keepalive `ws.on('pong', ...)` listener that the spectator handler has. Connections die ~30-60s after connect.
2. Bartender + memory-fragment generators fire LLM calls even with `LLM_API_KEY` empty, producing a 401 cascade that destabilizes user WS connections.

Both patched locally via `pnpm patch` (lives in `patches/@openpub-ai__pub-server@0.3.3.patch`). Drop the patch when Poe ships v0.3.4.

# Locked decisions from this session

- **Multi-provider via OPENAI_COMPATIBLE_VENDORS table.** All non-Anthropic providers reuse `OpenAIProvider` with vendor-specific `baseUrl` (and optional `endpointUrl` for Gemini). Anthropic stays on its own native adapter.
- **Ambient routing is opt-in, env-var driven.** `ROUTER_PROVIDER` + `ROUTER_MODEL_ID`. Without them, deterministic rules only.
- **Inter-agent ambient awareness is a non-goal at v1.** Agents wake on each other only via explicit `@`-mention. Router does not run on agent-originated messages.
- **Sandboxed agent workspaces stay sandboxed for now.** Shared workspace lands as its own future epic (probably alongside team-norms).
- **Local pnpm patch is the right vehicle for openpub-server fixes** until Poe ships v0.3.4. Patch travels with the repo via `patches/`.
- **DeepSeek for the whole brain (current default).** `deepseek-chat` for iter 1, `deepseek-reasoner` for iter 2+, `deepseek-chat` for the router. Doug wants to test all providers; this is just the current setup.
