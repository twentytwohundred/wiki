## Web search ... from stub to OpenClaw parity

A clean progression across 06-15/06-16:

- **`615.2259` ... `web_search` actually works.** Was a stub that always returned
  empty. Now backed by the Brave Search API (`BRAVE_API_KEY`, free tier ~2000/mo).
  No key → actionable status, not a silent empty. Network/HTTP errors surface as
  status, never throw. (xAI's keyless Live Search was the original plan; xAI
  deprecated it.)
- **`616.9` ... Brave + Google, bring-your-own-key + Settings panel.** Provider
  resolver (`WEB_SEARCH_PROVIDER`, else Brave preferred then Google). New
  **Settings → Web Search** panel (paste keys, see active provider, prefer one).
  OpenClaw migration carries search keys + provider choice.
- **`616.1257` ... Gemini grounding provider.** This is what OpenClaw actually uses
  for its "google" search (Gemini grounding, single key, no `cx` ... NOT the Custom
  Search JSON API). Migration now maps `gemini → gemini` / `brave → brave` from
  OpenClaw's real plugin path; unimplemented providers (grok, perplexity, exa)
  carry nothing and are named in the report instead of pinning a dead provider.
  This matches the `[[project_openclaw_web_search_schema]]` memory.
- **`616.1447` ... web-search keys hot-read from `runtime.env`.** Paste a key in
  Settings and the next search uses it ... no daemon/Agent restart. (Key *removal*
  still needs a restart ... the rarer case.)

## OpenClaw credential vaulting ... step 1 complete

- **`616.1518` (PR #312)** ... migration now vaults **every** secret-shaped value in
  `openclaw.json` (the whole `env` block + every `apiKey`/`token`/`secret`/`password`
  leaf wherever it lives), sealed per-Agent (`oc-<source-path>` names). Functional

  run showed `models.providers.*.apiKey` holds `${XAI_API_KEY}`, value already in

vault-canonical) is still deferred to pre-public, gated on master-key hardening ...
the vault's master key is still disk-resident today, tracked as a pre-public item.

## The Studio / pub-server saga (the big one)

One root-cause family, chased across many commits. The symptom Doug saw: Agents
(skippy/jodin) joined the Studio, then vanished ~60s later before answering, and
showed up duplicated / with a `(agent)` suffix. The chain:

1. **`616.2242` (PR #319)** ... Studio auto-provisioned on boot with every Agent
   enrolled (fresh + OC-migrated); room creation enrolls its own members so adding
   an Agent without `pub.identity` no longer dead-ends on `agent_pub_unprovisioned`.
   Solves the chicken-and-egg (provisioning needed a running pub, no pub existed).
2. **`616.2255` (PR #320)** ... enrollment no longer fails when an Agent's name
   matches the operator's (`skippy@valkyrie`): retries with a disambiguated label.
   (This introduced the `(agent)` suffix, removed in step 3.)
3. **`617.33` (PR #321)** ... shows each Agent **once, by real name**. Root cause:
   pub-server `0.3.3` has no `GET /agents/me`, so the "already registered?" check
   404'd and every Agent re-registered every boot, minting shadow ids (server keys
   uniqueness on display_name, no idempotency, no delete). Now trusts a recorded
   per-pub registration and skips the dead verify+re-register; member API collapses
   to one row per live Agent and hides un-deletable shadows. Also asks the operator's
   name (first-run + Settings → Your name). **Marked interim** pending a real
   pub-server verify/idempotency contract ... matches `[[project_pub_server_no_agents_me]]`.
4. **`617.54` (PR #322)** ... rename takes effect live: drops the supervisor's cached
   pub connection so it reconnects under the new name without a restart.
5. **`617.121` (PR #323)** ... `2200 update` restarts the daemon from the freshly
   installed binary in a clean child process (not in-process, which raced the
   `npm install -g` overwriting its own files), waits for the supervisor lock, and
   prints a loud `Run: 2200 daemon start` if it still doesn't come up.
6. **`617.256` (PR #324)** ... first stab at the ~60s drop: the pub-server's own LLM
   (Bartender persona + memory fragments) was unconfigured, so those calls 401'd and
   the failed broadcasts destabilized Agents' WebSockets. Ran the pub-server on the
   operator's fleet subscription via new `src/runtime/config/fleet-defaults.ts`
   (credential from sealed OAuth store, base URL from provider registry, model from
   catalog ... no literal at the call site). Added `grok-4.3` to the catalog. Also
   restarts running pubs when the ~6h OAuth bearer rotates.
7. **`617.327` (PR #325)** ... **corrected direction.** The real fix: OpenPub's
   agent-connection handler never resets socket liveness on `pong`, so its ping cycle
   kills each Agent ~60s after join. 2200 patches `server.js`, but the patch only
   applied via pnpm `patchedDependencies`, which `npm install` ignores ... so every
   real install ran the unpatched, agent-killing pub-server. The patched `server.js`
   now ships in `dist` and is overlaid onto the installed pub-server at launch
   (idempotent). **And the Bartender stays off** ... the same patch makes the
   Bartender + fragments clean no-ops with no `LLM_API_KEY`, and 2200 deliberately
   never gives the pub-server a credential. This **reverts** the 617.256 "run the
   Bartender on the subscription" direction ... the Bartender shouldn't be in the
   Studio at all. The Studio is the operator and their Agents, nobody else.
8. **`617.342` (PR #326)** ... fixes the overlay probe path (it looked in
   `dist/vendor/...` but the daemon's bundled entry is
   `dist/runtime/supervisor/bootstrap.js`, so the patch logged "no shipped patch
   found" and stayed unapplied). Probes each entry depth, takes the first that exists.
9. **`617.1222` (PR #327)** ... ambient router resilient to the SuperGrok concurrency
   limit. Every Agent in a room runs its own router LLM call to decide "should I chime
   in," so one untagged message fired N simultaneous grok calls → concurrency 403
   (`auth failed`) → router read it as "nobody responds" and cached that no-op. Now
   staggers each call with jitter, retries transient failures with backoff, never
   caches a transient failure. Plus **`@all` / `@everyone`** extend `@team`:
   deterministically wake everyone in the room, word-boundary guarded. Relates to
   `[[project_multi_agent_chatter_lessons]]`.
10. **`617.1255` (PR #328)** ... Studio chat history **persists**. OpenPub keeps only
    an in-memory window; 2200 now persists each pub's chat to
    `state/openpub/<pub>/messages.jsonl` and serves the merge of log + live window,
    deduped by id, trimmed to last 2000. No more blank screen on re-entry. Also
    tightened message spacing 28px → 12px.
11. **`617.1412` (PR #329)** ... the "web UI bound to a non-loopback address" notice
    is now one-time per bind (quick-setup binds `0.0.0.0` by design for LAN/Tailscale
    reach), instead of re-firing on every boot and flooding the inbox.

**Dependabot (PR #311 + others):** commander 14→15, react-easy-crop 5→6, plus a
grouped batch of 10 minor/patch; `verify:all` green across the combination, which
brought the published package back in line with `main`.
