## Decisions locked today (session 4)

- **Build-first, migrate-later.** Guppi's lean was to migrate Hobby into 2200 mid-build; Doug's call is to build the platform out fully, then move the seed team in. Cray principle reframed: the migration becomes a single deliberate event when the platform is feature-complete, not a chase-the-substrate exercise.
- **Permission set for Extensions is closed at v1.** Nine categories (tools / brain.* / notifications / schedule / pub.* / network / fs.scratch). New capabilities require a runtime change, not a manifest field.
- **Skill format admits a permissive subset.** Phase A accepts the broader ecosystem's loose convention (some files have just `name` + `description`) and preserves unknown frontmatter as `extras`. Phase B tightens when wrapping into Extensions.
- **Model catalog is hand-curated at v1.** No live polling against provider APIs in Phase A. Phase B can grow a polling layer; Phase C handles drift.
- **`pnpm cli` is the inline fallback.** `pnpm exec 2200` doesn't see workspace-root bins; `pnpm cli` (a script that resolves to `node ./dist/cli/main.js`) is the canonical inline form. The global symlink at `/opt/homebrew/bin/2200` (or `pnpm link --global`) is the "type 2200 from anywhere" experience.
