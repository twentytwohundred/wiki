## Probe-first: what the live surface actually looks like

Per the resolve-documented-gaps discipline, the OpenAI auth surface was probed
keylessly before any code. Three findings changed the build (recorded in the
decision record's implementation addendum):

1. **OpenAI's device flow is not RFC 8628.** JSON mint at
   `auth.openai.com/api/accounts/deviceauth/usercode` (returns `device_auth_id`,
   `user_code`, `interval` as a STRING, `expires_at` as ISO), poll at
   `.../deviceauth/token`, pending = HTTP 403 + `error.code:
   deviceauth_authorization_pending`. Verification page: `auth.openai.com/deviceauth`.
2. **The live discovery document is authoritative** and names
   `/api/accounts/authorize` + `/api/accounts/oauth/token` (the decision doc's
   `/oauth/*` constants respond as aliases). The implementation fetches
   discovery lazily, matching the xAI pattern.
3. **The mint is account-independent** ... a code mints fine even for accounts
   with the device-auth toggle OFF (the gate is at approval time). This shaped
   the fallback design below.

The poll's SUCCESS payload could not be observed keylessly; both plausible
shapes (direct tokens; authorization code + PKCE exchange) are handled behind
the verify boundary.

## What shipped ... PR #367

- **Provider-neutral subscription registry**
  (`src/runtime/oauth/subscription-providers.ts`). The six call sites that
  hardwired `xai-config` (LLM registry, refresh service, HTTP routes, CLI,
  first-run, providers DTO) drive off slug-keyed defs. Each def carries
  start/poll/refresh functions, display strings, a `transport` selector
  (`chat-completions` vs `codex-responses`), and an optional loopback flow.
  Kill switch for a provider = removing its def entry.
- **ChatGPT dual-flow auth.** Device-code primary (headless-friendly); loopback
  (`localhost:1455/auth/callback`, public client, PKCE) reachable two ways:
  explicitly (web card button "Use browser sign-in instead", CLI `--browser`)
  and as an automatic fallback ONLY when the device flow cannot START. A
  terminal outcome (user denied, code expired) never auto-falls-back.
- **Codex Responses adapter** (`src/runtime/llm/codex-responses.ts`) for
  `openai-subscription`: ChatGPT backend, Responses shape, mandated
  instructions scaffold, `store:false` + `reasoning.encrypted_content`,
  SSE aggregation, `chatgpt-account-id` from the bearer JWT. Hot-reads the
  sealed fleet token per request (xai pattern). ALL wire details in one
  exported `CODEX_RESPONSES_WIRE` block, marked interim/unverified.
- **Peer positioning.** Settings shows SuperGrok + ChatGPT as equal cards
  ("bring a subscription you already pay for"); first-run offers each in turn;
  `2200 oauth openai <login|status|logout>` joins the CLI. Fixed the stale
  Grok login/logout copy that claimed an `XAI_API_KEY` fallback that never
  existed.
- **Models.** Catalog + zero-rated pricing entries for the Codex family
  (`gpt-5.1-codex`, `-max`, `-mini`) under `openai-subscription`; the picker's
  Subscriptions optgroup picks them up through the existing mechanism.

## Self-review before merge

Ran an eight-angle adversarial review (3 correctness, reuse/simplification/
efficiency, altitude, conventions) with one finder agent per angle. Highest-value
catches, all fixed with tests in the final commit:

- The loopback fallback was **unreachable for the accounts it was built for**
  (mint never fails for toggle-off accounts) ... hence the explicit browser
  entry points above.
- CLI/first-run **fell back on user-denied consent** (masking the denial and
  hanging headless boxes on a browser flow) ... start-failures are now a
  distinct error type and the only fallback trigger.
- An abandoned loopback sign-in **held port 1455 for 15 minutes** and 409'd all
  retries (no server-side cancel path) ... login/start now tears down the
  prior session per provider before binding; expired sessions are swept.
- One 502/429 from the ChatGPT poll was **terminal** mid-approval ... now
  transient, matching the outcome contract.
- A sparse `status:'failed'` Codex response **read as a successful empty
  completion** ... now throws.
- The subscription entries' placeholder env keys let the generic key routes
  **clobber the API-key sibling's credential** (`openai-subscription` CLEAR
  deleted `OPENAI_API_KEY`) ... rejected server-side, key controls hidden on
  subscription cards. (This also existed for xai-subscription / `XAI_API_KEY`
  since May; fixed for both.)
- Clock skew could make OpenAI's absolute `expires_at` look pre-expired
  (instant timeout) ... floored with headroom.
- `runDeviceFlow` was deleted: after the registry refactor it had zero
  production callers and its poll loop had been duplicated into the driver.
  One loop remains; wire blocks are tested directly.
- Token-store wrapping key memoized per home ... subscription providers
  decrypt the sealed token on EVERY LLM request (deliberate), and each request
  was re-reading master.key + salt and re-running HKDF.
