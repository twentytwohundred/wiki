### Cluster 1 ... valkyrie-driven live-update hardening (`.623.x`)

Four releases in one day, all traced to real failures hit on the live valkyrie box
during `2200 update`:

- **`2026.623.1350`** ... the pub-server patch-overlay decision extracted to a pure,
  unit-tested `planPubServerPatch`. No behavior change; a regression guard for the
  "shipped-twice" (`617.327` then `.342`) depth bug that let Agents get silently
  dropped from the Studio after ~60s.
- **`2026.623.1612`** ... `supervisor-bounce-survival` chaos test flake fix
  (reconnect wait 25s→60s, budget→150s) under parallel CI load. Test-only.
- **`2026.623.1638`** ... Studio HTTP 409 after `2200 update`. A pub-server can
  outlive its supervisor and keep holding its port; the next boot collided on
  `EADDRINUSE`, flipped the pub to `errored`, and every post returned 409 with a
  healthy pub-server sitting right there. `startPub` now inspects the port first and
  **adopts** a healthy pub-server (pure `planPubPort`). Hit live on valkyrie.
- **`2026.623.1702`** ... `2200 update` over SSH left the daemon down. The restart
  was `await`ed with inherited stdio, tying the new daemon's startup to the update
  process ... which over SSH exits the instant the command returns. Restart is now
  spawned **fully detached** (`setsid`, no inherited stdio, `unref`'d) with liveness
  confirmed by polling the supervisor lock. Observed live on valkyrie.
- **`2026.623.1738`** ... QA hardening. `scripts/smoke-install.sh` (`pnpm smoke`)
  packs the tarball, installs it clean in `node:22`, and asserts the regression
  classes that have actually bitten (keyless `setup`, pub-server patch applies,
  Studio auto-provisions + dedupes, no LLM credential on the pub, restart without a
  port collision, chat persists). Wired into CI (`.github/workflows/smoke.yml`).
  Chaos tests moved to an isolated `vitest.chaos.config.ts` (dedicated CPU is the
  real flake fix, not the earlier timeout band-aid).

### Cluster 2 ... SuperGrok-only onboarding (`.622.2027`)

A SuperGrok-only install (no API key) fell through to the keyless `local` fallback
because the default provider pick only looked at `runtime.env` keys, never the
`xai-subscription` credential in the sealed fleet OAuth store. The pick now counts
an active subscription as a real credential (pure `pickOnboardingProvider`). One
SuperGrok sign-in is all an operator needs ... no second model, no API key. This is
the answer to Doug's "should one OAuth be the only model needed" ... yes, now.

### Cluster 3 ... the ~6h Agent-silence fix (`.624.1204`)

An Agent bound to `xai-subscription` captured the OAuth bearer once, at spawn. The
fleet bearer is ~6h-lived and the background refresh rotates it, but a running Agent
never picked up the new one ... so once its cached copy expired, **every** LLM call
403'd: the ambient router (nobody chimes in, member dots stay grey) and the main
loop (even an @-mention can't reply). The `xai-subscription` provider now reads the
bearer **fresh from the sealed store on every request** (one decrypt, no network), so
a rotated fleet token is used immediately with no restart. This is the root cause of
the "grey icons + Jodin won't wake" symptom Doug reported. Static API keys are
unchanged (still captured once).

### Cluster 4 ... the fleet restart button (`.625.1807`)

Settings → System now has a **"Restart all Agents & services"** button for when an
Agent wedges (stuck `blocked_on_agent`, no longer responding). One click bounces
every pub-server, Agent, and connector gateway WITHOUT restarting the daemon (it
stays up to serve the request). Two-step inline confirm, result reports how many came
back. Backed by `POST /api/v1/system/restart` → `Supervisor.restartFleet()`.
Validated live on valkyrie (restarted studio + skippy + jodin, all ok).

## Pre-public QA sweep ... four parallel reviews

Ran four independent review agents against the tree (status/docs, first-run critical
path, defensive security, web-app completeness). `pnpm verify:all` is green (2234
runtime + 111 web tests). The only red CI is a dependabot bump tripping new Prettier

the priority order for the final push:

**Tier 0 ... stranger-path blockers (the demo dies without these):**

1. **Fresh install never gets a Studio.** `ensureStudioPub` only runs at daemon boot
   with Agents already on disk; the onboarding `/confirm` path (`server.ts:4189`)
   runs `migrateFromHandoff` → `startAgent` but never creates the Studio. On a real
   single-boot fresh install the first Agent has no room to appear in, and its seeded
   orientation post targets `pub_name: 'studio'` so its debut fails too. **Verified by
   hand this session.** Looked fine on valkyrie only because that box already had
   Agents from a prior boot. Fix: trigger `ensureStudioPub` from Agent create/confirm.
2. **Provider failure during the interview is swallowed** (`session.ts:336-406`) ...
   onboarding "succeeds" with an Agent bound to a dead provider. The `local` endpoint
   is never reachability-checked on the web path. Surface the error; validate local.
3. **CLI-wizard API keys are dead until a daemon restart the wizard never performs**
   (`first-run.ts:162`) ... `restartDaemonForMigratedKeys` already exists, just isn't
   called. SuperGrok OAuth is unaffected (hot-read).
4. **Main chat screen silently eats failed sends + spins "Thinking…" forever** if the
   Agent dies mid-reply (`AgentDetailScreen.tsx:203-341`). This is the screen every
   demo lives on. Add an error surface + a `pendingTaskId` timeout.
5. **Name normalization throws unrecoverable 500s** ("2200", CJK, emoji, "Mira"
   collision) with no rename control in preview (`identity-from-interview.ts:190`).
   Normalize-or-fallback, pre-check collisions, surface the real error.

**Tier 1 ... security before strangers (the network edge).** Crypto/file-perm hygiene
is clean (0600/0700, PKCE S256, constant-time compares, no committed secrets, tight
npm `files` allowlist). The exposure is at the transport edge. The exploit-level
detail (specific routes, mechanisms, file:line) is deliberately **kept out of this
public wiki** and delivered to Doug directly, since the issues are unpatched and
several live instances bind non-loopback today. Category summary:

- **CRITICAL ... default network bind + bearer transport posture.** The default LAN
  bind + static bearer over plain HTTP is exploitable by a passive LAN observer.
  Recommend: default loopback + Tailscale, non-loopback as explicit opt-in.
  Install-contract change (touches Simon's `install.sh`) ... Doug's call.
- A small number of **auth-coverage and token-scope drifts** at the HTTP edge to
  tighten before external hands touch it.
- An **OAuth discovery-metadata** hardening item.
- **An operator credential-at-rest item flagged to Doug directly** (rotate + tighten
  file mode). No repo change; not a code bug.
