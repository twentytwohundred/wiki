# Handoff ... 2026-07-24 (Hobby)

Session purpose: Doug reported three things ... Agents need a way to
keep a directory structure, he needs to see and edit their files in the
browser, and asking one Agent a question that routes through the Studio
leaves the first Agent stuck forever.

First session on Opus 5.

## What the three asks actually turned out to be

**1. Directory structure ... already shipped.** Agents have had
`/project`, `/shared`, `/brain`, `/commons` since Epic 2, resolved by
`storage/path-resolver.ts`, with `fs_write` creating parent dirs. No
work needed. The gap was purely that nothing outside the Agent could
see any of it.

**2. Browser file surface ... genuinely missing.** No file routes
existed at all.

**3. The stuck Agent ... three separate causes**, all presenting
identically to the operator, diagnosed against the on-disk state in
`~/.local/share/2200` (730 done, 162 errored, 90 blocked_on_detector,
and **9 stuck in `running`**).

## The stuck-Agent diagnosis

**Cause A ... orphaned `running` tasks, silent and permanent.**
`pickPending()` only returns `pending`; `tickTaskPoll()` flips a task to
`running` before the loop runs it; nothing reconciled `running` at boot.
Any task in flight when the process died was lost forever ... never
retried, never errored, never surfaced. The standing
full-fleet-restart-after-every-build practice fires this on every
mid-flight task.

The evidence was exact.
`agents/simon/tasks/task_a962038cb59d4dccbf35a2f01b5df8d8.md`, titled
"Simon, can you ask Hobby how many API keys he has in his vault?",
sits in `state: running` with `outcome: null`. The continuation
machinery had worked perfectly: Simon parked, Hobby answered in the
studio, the wake source resumed the task and appended "Continuation:
response arrived". Then the process died and it never moved again.
Simon has a *second* `running` task from 44 seconds later, which is
impossible in one process lifetime given the `taskInFlight` guard ...
proof of repeated deaths.

**Cause B ... the parked-task resume sat behind the anti-chatter
guard.** Full reasoning in
[[decisions/2026-07-24-parked-wait-outranks-directedness]]. Short
version: `findWaiting` lived inside `enqueueSyntheticTask`, downstream
of the `directed_to` resolver and the Epic 3.8 "sender is an Agent →
return" guard. A peer answering in plain prose (no `@mention`, no
`reply_to` ... how Agents actually talk in a two-party Studio thread)
never reached the resume. The parked task stayed blocked until the
timeout sweep while the answer sat in the room.

**Cause C ... `chat_send` had no thread.** It wrote unconditionally to
the legacy single-thread log, which the multi-store surfaces only as
the `default` chat. An Agent answering a question asked in any other
thread put the answer where Doug was not looking.

Plus `expected_from` matching was exact against the wire display name,
and that string is model-authored (`@Alice` vs `alice`).

## What shipped

Branch `fix/orphaned-tasks-and-pub-resume`, three commits.

**Commit 1 ... the stuck-Agent fixes.** New
`src/runtime/agent/orphaned-tasks.ts` sweeps at Agent boot before the
poll timer starts. `tryResumeParked` hoisted ahead of every rule and
guard, on both the live path and the sweep backstop. `expected_from`
normalized. `chat_send` routes to the thread its task came from, read
off `ctx.taskSource` rather than a new argument ... "the model forgot to
pass it" is the failure class being fixed, not a tool to reach for.

**Commit 2 ... the file surface.** `src/runtime/http/files.ts` plus four
routes (tree / content / save / raw download). Containment comes from
`resolveVirtualPath` with the target Agent as calling agent, so it
inherits the Agent fs tools' guarantees exactly. It deliberately does
not run the Agent perm evaluator ... that answers "may this Agent touch
this path", a different question from "may the operator read their own
Agent's files". `/brain` is readable but not writable here (raw writes
behind the FTS index leave search stale; the rejection names the Brain
screen rather than just denying).

Web: `/agent/:name/files` plus a Files tab on the Agent screen. Tree
left, viewer right, inline editor, Download. Binary and >1 MB files
offer download instead of a broken editor; read-only files never render
an Edit button rather than failing at save.

Chat linkification (`apps/web/src/chat/filePathLinks.ts`) is what makes
"present a file to me" work with **no new tool and no prompt change** ...
Agents already say where they put things, so that sentence becomes the
handoff. Written as a remark plugin, not a string replace, so paths
inside code fences / inline code / existing links are never touched.
Operator-typed paths are not linkified. No new dependency.

**Commit 3 ... age gate on the requeue.** Caught before it shipped:
Doug's box has orphans back to April 27, and requeuing those blind would
have Agents abruptly answering three-week-old questions. Orphans over
24h now error as `stale` instead. The window sits above the eight-hour
autonomous-run target so a genuinely long task still survives a
restart.

the base tree ran it clean 6x. Filtered the temp files; added `rm`

- **The unparked-relay hole remains.** All of this assumes the model
  actually calls `task_await_response`. If it posts the question and
  ends its turn without parking, there is no task to resume and the

  end; `incomplete-turn.ts` is the closest existing machinery.
