## The fluid setup path (released `2026.614.1818`)

New **`2200 setup`** command (non-interactive, idempotent) that the installer runs as its final step, so `curl | sh` flows straight through with no stops:
- inits `2200_HOME` (default), mints a user identity (display name = `$USER`, renamed later in-app), starts the daemon ... zero prompts.
- binds the web server to the LAN (`0.0.0.0`, persisted via `TWENTYTWOHUNDRED_WEB_HOST`) so the printed URL is reachable from another device.
- auto-migrates OpenClaw when `~/.openclaw` is present (Agents come over ... no first-Agent walk-through).
- prints the access block: `http://<lan-ip>:2200/?token=<bearer>` (the web app already reads `?token=` from the URL, persists it, strips it), localhost fallback, bare token.

Also: the installer's npm-prefix fix now auto-applies with narration (was a yes/no stop ... it's reversible plumbing; `--no-prefix-fix` opts out; `--no-setup` installs the CLI only). The interactive `2200` first-run also ends at the web URL now (shared `printWebAccess`) and skips the build-an-Agent push when one was migrated.

**Validated end-to-end in clean `node:22` containers** (built + packed the tarball, installed it, ran the flow): fresh → non-localhost LAN URL + token + daemon up; fake `~/.openclaw` → auto-migrate + "your migrated Agent 'skippy' is already there"; second run idempotent.
