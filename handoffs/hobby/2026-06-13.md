## The premium installer + zero-flag OpenClaw migration (PR #277, released `2026.613.1445`)

Doug's brief: make the installer *really* good ("look like we spent the months we did"), and auto-offer OpenClaw migration **only when detected, never for blank users, no flag**.

**Approach.** Ran a 4-agent research/mapping workflow (premium curl|sh installer patterns from rustup/bun/starship/uv; a portability audit of the old installer; the first-run injection map; the OC surface). Then a 3-agent adversarial review of the rewrite. Pulled the brand from the repo's own design tokens ... **green-for-alive**, accent `#22c97a`, near-black `#0a0d10`, JetBrains Mono. (Note: 2200 has no logo glyph; the favicon is a status light. The wordmark I built is a block `2200` + a green `●` dot + "green for alive" tagline.)

**Installer (`install.sh` rewrite).** Block `2200` wordmark + tagline in **truecolor #22c97a** (256 fallback), a **braille install spinner** over captured npm output, ✓/✗/! glyph triad matching the fleet-state palette. Correctly gated: full art only on an interactive UTF-8 terminal; piped/CI gets a clean one-liner with zero escape leakage; NO_COLOR/FORCE_COLOR honored. The research + adversarial review found **8 real bugs in the OLD installer**, all on documented happy paths ... most important: `--help` was broken under `curl|sh` (sed on `$0`), and the npm-prefix-change consent was structurally unreachable under `curl|sh` so it **silently edited the user's shell init files**. Now prompts via `/dev/tty`. (Full list in the CHANGELOG + PR.)

**Zero-flag OC migration.** Installer detects `~/.openclaw` → seeds the banner (non-TTY safe). The bare-`2200` first-run wizard then offers migration automatically, only when OpenClaw is present (a blank user never sees it). Runs through the daemon's `cli.build.from-handoff` RPC ... no migrate-vs-daemon state-file race (this was the load-bearing ordering insight: the daemon is already up by that point, so route through it rather than a second in-process Supervisor). Copies OC LLM keys into `runtime.env` (no re-auth wall), prints report + checklist + disable guidance. Every failure path non-fatal.

**Security (from the adversarial review, two HIGH).** `collectOpenClawLlmEnv` is now an explicit **LLM-provider allowlist**, not a `_KEY$`/`_TOKEN$` suffix heuristic ... it was sweeping up `GITHUB_TOKEN`/`AWS_SECRET_ACCESS_KEY`/`STRIPE_API_KEY`/channel tokens. And `upsertRuntimeEnvKey` now **chmod 0600 on every write** (the mode only applied on file creation, so an existing `runtime.env` kept looser perms while we wrote provider secrets into it ... affects the API-key paste path too, not just migration).

**Validation.** `pnpm verify:all` green (182+14 files, 2,123+95 tests). Installer run in clean `node:22` containers across three environments: piped root (ASCII/no-color fallback), non-root prefix-fix + OC-detection seed, and the **full TTY/truecolor/UTF-8 premium path** (block wordmark + braille spinner confirmed via byte markers: 105 truecolor-accent escapes, 102 `█`, 95 braille frames, cursor hide+restore both present).
