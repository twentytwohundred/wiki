### The Spotify API migration discovery (real diagnosis night)

With Grok-Jodin actually trying the right tools, we surfaced the
real bug. `spotify_create_playlist` returned 403 Forbidden with
"Bad OAuth request" even though:

- The token was fresh (1-hour expiry, just minted)
- The scope set was correct (`playlist-modify-private` for
  `public: false` calls)
- All read-side Spotify tools (search, get_my_playlists, get_devices)
  worked cleanly with the same token

Doug's first instinct (and Jodin's) was "re-authenticate." Spotify's
own error response actually says "re-authenticating the user won't
help here" — but we missed that signal twice.

Doug suggested adding himself to the app's User Management. Tried;
still 403. So allowlisting wasn't the root either.

The actual fix: bypass the SDK, hit Spotify directly with curl using
the vault token. Created a "Sunday Afternoon Test" playlist
successfully via `POST /v1/me/playlists`. Same token, different
endpoint shape. Discovery: **`@spotify/web-api-ts-sdk` v1.2.0 calls
endpoints that Spotify deprecated in the Feb 2026 API migration.**

| What the SDK calls | What Spotify accepts now |
|---|---|
| `POST /v1/users/{user_id}/playlists` | `POST /v1/me/playlists` |
| `POST /v1/playlists/{id}/tracks` | `POST /v1/playlists/{id}/items` |

Both deprecated endpoints return 403 Forbidden with the generic
"Bad OAuth request" message that throws every reasonable reader
off the scent. Patched both via the SDK's `api.makeRequest()`
method — bypasses the broken endpoint paths while keeping the
SDK's auth + refresh machinery intact.

After the patch, Grok-Jodin re-ran the task and successfully created
the playlist + populated it with the curated tracks. **First green
end-to-end run.**

6. Second upload attempt: 400 Bad Request → macOS `base64`

7. Third attempt: **HTTP 202 Accepted**. Cover URL on the playlist
   flipped from the auto-mosaic CDN to the uploaded-image CDN.

## Known follow-ups (carried + new)

1. **Orphan-PID detection at registration** (session-14 #2). Bit us
   hard tonight across multiple daemon-restart and agent-stop cycles.
   Up to 4 jodin processes were alive simultaneously at one point.
   The supervisor should reject a new register when a different live
   PID already holds that name, or force-kill the previous PID before
   accepting the new registration.

2. **Detector remediation hook**. When error_storm trips from a known
   class (credential, scope, rate-limit), the loop should inject a
   forcing system message on resume so the model gets an explicit
   "do not retry the same tool with the same args" instruction. Pure
   retry-after-pause didn't change Jodin's behavior tonight.

3. **`2200 brain reseed` command** (session-14 #3). seedStarterPack
   only writes missing notes; updates to the seed source don't
   refresh existing notes in already-onboarded agents. We bumped
   tool counts and added image_generate documentation in this
   session; existing agents on this instance won't see it until a
   reseed mechanism lands.

4. **Pub-server bounce chaos test** (session-14 #4). Still open.

5. **Pre-existing parallel-test flake** in
   `tests/runtime/supervisor/` (session-14 #5). Hit again tonight.

6. **Loop decomposition** (session-14 #6). Deferred until after v1.

7. **Vault-store of OAuth client_id**. Tonight we worked around the
   env-coupling by adding the spotify vars to `runtime.env`, but
   the cleaner architectural fix is to store client_id (and secret,
   for confidential flows) in the credential vault alongside the
   access token. Removes the supervisor-env coupling entirely and
   makes per-Agent OAuth credential isolation possible (different
   bot accounts per agent if ever desired).

8. **Studio observability for "Thinking" state**. Doug raised this
   explicitly: the UI shows a spinner but doesn't surface what the
   agent is actually doing (which tool just fired, what came back,
   what's pending). A streaming tool-call view alongside the chat
   would solve the "I have no idea if he's stuck or really
   thinking" problem.

9. **Studio state-sync**. UI showed PAUSED while supervisor said
   blocked_on_detector and rejected the Start click. Real bug.

10. **Model-anchoring guardrails**. The DeepSeek-vs-Grok contrast
    tonight was sharp enough to warrant either a) a system-prompt
    rule against narrating completion without a corresponding tool
    call in the same turn (small), or b) a loop-level audit that
    flags narrated-completion-without-tool-call as a soft warning
    to Doug (medium). The hard-coded rules in Jodin's brain note
    are a brain-level mitigation; the durable fix lives higher up
