## Real frictions surfaced

Two real issues that the runbook now documents but that should be considered for hardening fixes:

### 1. Stale CLI binary causes silent OAuth flow hangs

The first GitHub OAuth login hung indefinitely on the token-exchange `fetch()` ... browser callback fired, redirect server captured the code, but the bundled token-exchange code in `dist/cli/main.js` was a stale Apr 25 build. `pnpm build` rebuilt it; the second attempt succeeded immediately. **No "binary out of sync with source" guard exists on the canonical install path.** This is the same shape of issue I'd expect to bite future contributors. Worth a small Phase D-of-9 follow-up: either auto-rebuild on CLI invocation if dist is older than src, or add a startup warning when dist mtime < newest src mtime.

### 2. The wrong-clone trap

The running supervisor was spawned from `~/code/2200/dist/...` ... the OLD `~/code/` clone outside the canonical project root. CLAUDE.md says "never write to `~/code/`"; the rule was already violated by an earlier setup. Stopping the supervisor and restarting from the canonical Dropbox-tree CLI brought everything onto the canonical clone path, but the existing `~/code/2200/` clone is still on disk and the supervisor will sprawl back to it if any future `2200 daemon start` runs from that directory. **Worth a separate cleanup task to delete the `~/code/2200/` clone outright** ... currently it just sits there as a sprawl trap.

### 3. Supervisor env inheritance bites on restart

The new supervisor spawned from my Claude Code shell did not inherit `DEEPSEEK_API_KEY` and hobby crashed on start with `env var 'DEEPSEEK_API_KEY' is not set`. Fixed by sourcing `~/.config/2200/oauth-apps.env` (where Doug parked the key) before `2200 daemon start`. Documented in the runbook. **Worth a hardening fix: have the daemon-start CLI explicitly source a known location (e.g., `~/.config/2200/runtime.env`) before exec.** Avoids the friction of "remembered to source the env file before launching."

## Phase D-of-9 hardening landed end-of-session

After the manual-test sweep closed, Doug greenlit cleaning up the three frictions while it was all fresh. Branch `epic-9-phase-d-hardening`:

### Build-freshness check (`src/cli/freshness-check.ts`)

CLI startup-time check: if `dist/cli/main.js` is older than the newest `.ts` in `src/`, emit a yellow stderr warning. Walks the src tree iteratively (stack-based, short-circuits on first newer file). Skipped silently in packaged installs (no co-located `src/`). Skipped via `TWENTYTWOHUNDRED_SKIP_FRESHNESS=1`. 6 unit tests including non-existent paths, deep src trees, env-var override.

### Runtime-env auto-source (`src/runtime/config/runtime-env.ts`)

Parser + loader for bash-style `export KEY=value` files. Strict key regex `[A-Z_][A-Z0-9_]*`, optional `export ` prefix, surrounding-quote-pair stripping, line-numbered parse errors. 17 unit tests covering parse cases, file IO, and the default path resolution.

`spawnDaemon` (`src/runtime/supervisor/daemon.ts`) reads `~/.config/2200/runtime.env` at spawn and merges with `process.env` for the supervisor child. Agent processes the supervisor later spawns inherit the merged env. Telemetry on the spawn log includes `runtime_env_loaded` count + path. New options: `runtimeEnvPath?: string | null` for tests/overrides. 3 new daemon tests covering missing file, disabled load, and parse error abort.

### Env file split

- `~/.config/2200/oauth-apps.env` ... OAuth-app provider creds (sourced manually for `2200 oauth login`).
- `~/.config/2200/runtime.env` ... long-lived supervisor secrets like `DEEPSEEK_API_KEY` (auto-sourced on `2200 daemon start`).

Both mode 0600, both off Dropbox. Different lifecycles, different threat profiles, cleanly separated.
