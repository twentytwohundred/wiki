### PR #210 ... wire capabilities[] through interview → handoff → Identity

Closes the loop. Chain now end-to-end:

```
interview transcript intent_tags
  → suggestCapabilities (auto-apply default_on)
  → buildHandoffFromTranscript (capabilities arg)
  → HandoffFrontmatterSchema.capabilities
  → buildIdentityFromHandoff (propagates to Identity)
  → orchestrator pre-renders walkthrough
  → orientation embeds Phase 4 walkthrough script
  → Agent calls credential_request on first wake
```

Specifics:
- `HandoffFrontmatterSchema`: `capabilities: z.array(z.string()).default([])` (mirrors `mcp_servers`).
- `buildIdentityFromHandoff`: propagates `fm.capabilities` into Identity (the orchestrator already reads `built.frontmatter.capabilities`; this lights it up).
- `buildHandoffFromTranscript`: accepts `capabilities?: readonly string[]`.
- `OnboardingSession.runSummaryStep`: loads the catalog, runs `suggestCapabilities` against transcript `intent_tag`s, auto-applies every `default_on` (high-confidence) suggestion. Lower-confidence entries land in `SessionPreview.capabilities` for the future operator-override UI.
- Refactor: `resolveCatalogDir` extracted from orchestrator to `capability-loader.ts` so both call sites share one implementation.

5 new tests (197 total): handoff-to-Identity round-trip, interview-to-handoff plumbing, session end-to-end with a temp fixture catalog whose tags overlap the test SCRIPT goal ids (overlap=3 → default_on → auto-applied → handoff.capabilities=['testbed']).

**Opinionated call:** auto-apply every `default_on`, no extra cap. The suggester's ≥2 tag-overlap threshold is already the filter. Surfaced in the PR description for visibility.
