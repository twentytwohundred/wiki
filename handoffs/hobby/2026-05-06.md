## What shipped

### Epic 12 Phase B substrate (PR #115, MERGED)

The `2200 extension install / uninstall / update` lifecycle on top of the Phase A registry. The shape is the in-process v1 with permission-kernel-chokepoint that `wiki/prior-art-analysis.md` §Epic 12 calls out: child-process boundary, strictly whitelisted env, captured stdio, 30s timeout, microVM future replaces the boundary as a substitution rather than a redesign.

What landed:

- **CLI verbs**: `extension install <path | github:owner/repo | https://github.com/...>` with `--yes` / `--force`, `extension uninstall <name>` with `--yes`, `extension update <source>` with `--yes` / `--allow-same-version`.
- **Hook executor** (`src/runtime/extensions/hooks.ts`): whitelist `PATH/HOME/LANG/LC_ALL/TZ` only, no parent secrets passing through; capability-derived env (`EXTENSION_NAME`, `EXTENSION_PERMS`, `EXTENSION_SCRATCH_DIR` only when granted, `EXTENSION_FROM_VERSION/TO_VERSION` for update); cwd = install dir; SIGTERM → 2s grace → SIGKILL with detached process group so bash-forks-sleep doesn't leak past timeout; stdout+stderr captured to `<home>/state/extensions/<name>/<hook>.log`.
- **Permission grants** (`src/runtime/extensions/grants.ts`): persisted at `state/extensions/<name>/grants.json`, Zod-validated, name-vs-dir checked. Runtime intersects manifest declarations with persisted grants, so an Extension cannot escalate post-install.
- **Per-Extension state** (`src/runtime/extensions/state.ts`): 1 MiB JSON bag at `state/extensions/<name>/state.json`, plus optional `scratch/` directory when `fs.scratch` granted.
- **Source resolution** (`src/runtime/extensions/source.ts`): local dirs (absolute / relative / `~`) and public GitHub URLs (`https://github.com/owner/repo` and `github:owner/repo` shorthand) via `git clone --depth=1`. Other sources throw `UnsupportedSourceError` ... npm + marketplace land in a later sub-phase.
- **Install orchestrator** (`src/runtime/extensions/install.ts`): copy → grant → init state → run hook → roll back on failure; backup-then-swap-then-hook with revert for update; teardown-after-hook for uninstall (always removes files even when the hook fails ... a misbehaving Extension cannot pin itself in place).

58 new tests on top of the 1054 that passed yesterday. End-to-end CLI smoke against the built bundle: install with permissions surfaced, capability env exposed to hook, log captured, uninstall hook ran, state torn down. Sample log:

```
hook=install  version=0.1.0  cmd="bash .../install.sh"
install hook for smoke-ext v0.1.0
perms: fs.scratch,network
scratch: .../state/extensions/smoke-ext/scratch
exit=0 signal=null duration_ms=7 timed_out=false
```

### Epic 11 Phase B substrate (PR #116, OPEN)

User-facing `2200 skill install` / `uninstall` verbs that mirror the Extension lifecycle, plus the in-memory synthesizer that wraps a ParsedSkill in an `ExtensionManifest` shape so the AgentLoop can consume Skills and Extensions through the same code path in the next sub-PR.

What landed:

- **`2200 skill install <source>`** with `--force`. Reuses the Extension source resolver (local dirs + public GitHub). Validates SKILL.md, copies the directory (incl. sibling reference files) into `<home>/skills/<name>/`, re-reads via the existing registry to confirm.
- **`2200 skill uninstall <name>`** with `--yes`. No hooks (Skills are pure-data at v1).
- **`synthesizeSkillManifest(skill)`** (`src/runtime/skills/wrapper.ts`): builds an in-memory `ExtensionManifest` from a `ParsedSkill`. Maps `tools` → `ExtensionTool[]`, derives Title-cased `display_name` from kebab slug, falls back through `extras.author` → supplied default → `'unknown'`. Result passes `ExtensionManifestSchema` so any code path that already speaks Extensions can consume Skills without special-casing.
- **`findSkillExtensionConflicts(home)`**: reports slugs that exist as both Skill and Extension. Helper for the AgentLoop wiring next sub-PR (the "rename one" message).

18 new tests. End-to-end smoke (install / list / show / uninstall) all green against the built CLI for a typical SKILL.md with frontmatter, tags, tools, and body.

## Notes for future-me

- The hook executor's detached-process-group kill is load-bearing and surfaced as a real bug only because of the `bash + sleep 30` test case. Worth keeping in mind for any other place we spawn user-supplied scripts: SIGTERM to bash does NOT propagate to the children it execs, so killing the immediate child is insufficient.
- The `synthesizeSkillManifest` function is a forward-looking helper. It's tested but has no caller yet ... that lands in Phase B-2's AgentLoop wiring.
- `findSkillExtensionConflicts` likewise has tests but no caller yet. Same lands-with-AgentLoop-wiring pattern.
- The Extension install orchestrator's `validateApproval` rejects approvals that include permissions not in the manifest. This is a defensive check ... a buggy CLI handing the orchestrator an inconsistent decision should fail fast. Tests cover this so future edits to the CLI prompt flow can't regress it.
- Source resolution's GitHub support uses `git clone --depth=1`. Public repos only at v1. Private repos + non-GitHub hosts wait until per-source token storage lands alongside the marketplace work.
