### Afternoon ... build the substrate

All schema additions are non-breaking (defaults). Three test fixtures gained `connectors: []` to satisfy the now-required field in `IdentityFrontmatter` output type.

**Routing (`src/runtime/connectors/router.ts`).** Pure-function `routeInbound({event, identities, mentionDetector?})` returning per-Agent decisions: `pass` / `pair` / `block` with reason codes. The supervisor's HTTP handler is the wake source; per-Agent `ConnectorWakeSource` is unnecessary because inbound is webhook-pushed, not subscribed.

**Inbound endpoint (`src/runtime/http/server.ts`).** New `POST /api/v1/connectors/:connector_id/inbound`. Validates payload (Zod), enumerates known Identities, runs router, creates synthetic tasks on Agents that pass. Pairing requests log-only for v1 (operator-notification fan-out is a follow-on). Loopback-only; bearer-token gating deferred to the install-flow work.

**WhatsApp connector package (`apps/whatsapp-connector/`).** New pnpm workspace package, depends on `@whiskeysockets/baileys@7.0.0-rc11` + `qrcode-terminal`. Single entry script `src/gateway.ts` (~290 lines):

- `useMultiFileAuthState(AUTH_DIR)` persists Baileys session across restarts (so QR scan only happens once).
- On `connection.update` with a `qr`, the gateway prints an ASCII QR to stderr via `qrcode-terminal`.
- On `messages.upsert`, the gateway extracts the text + sender JID + conversation JID, normalizes to a `ConnectorInboundEvent`, POSTs to the supervisor's `/api/v1/connectors/whatsapp/inbound`. Self-echo and status broadcasts filtered.
- HTTP listener bound to `127.0.0.1:GATEWAY_PORT` exposing `POST /outbound` ... receives `{to, body}`, calls Baileys `sock.sendMessage(to, {text})`. The `whatsapp_send` baseline tool POSTs here.
- At startup the gateway writes `<home>/state/extensions/whatsapp/gateway.json` (port + account + pid + started_at) so the `whatsapp_send` tool can discover the port. Removed on SIGTERM/SIGINT.

**Outbound tool (`src/runtime/tools/baseline/whatsapp.ts`).** New `whatsapp_send` baseline tool ... reads gateway.json, POSTs `{to, body}` to the gateway, returns `{status, message_id, to}`. Throws `gateway_not_running` if the file is missing or the gateway is unreachable. Baseline tool count is now 40 (`BASELINE_TOOL_NAMES` bumped from 39).

## Task continuation primitive ... new substrate

Decision: [[../decisions/2026-05-16-task-continuation-primitive]].

The bigger architectural win. Failure mode caught on first Discord test: Simon told Doug "I'll relay Hobby's answer" then never did. Each wake source created Tasks in isolation; the peer reply on surface B had no causal link to the original surface A request.

Rejected: brain-note open-loop pattern (Doug: continuity needs to be substrate, not Brain). Rejected: prompt-only nudge. Built the structural primitive instead.

Shape:
- Task model gains `wait_for` block (source_kind, source_ref, expected_from, expires_at, context_note, waiting_since). Round-trips through YAML; legacy task files load cleanly.
- New baseline tool `task_await_response` writes `wait_for` + state=`blocked_on_agent` to disk, registers an `external_response` blocker so the loop exits cleanly. Agent process goes idle for the task.
- New blocker kind `external_response` + new loop exit kind `blocked_on_agent_response` (distinct from `blocked_on_user` which has poll-back-to-life semantics for credential paste flows).
- Supervisor's inbound router does match-before-create at all three inbound paths (connector inbound, chat-message POST, pub wake-source). If a matching wait_for exists, the inbound is appended as a `## Continuation:` section to the existing task body and state flips back to `pending`. Otherwise the existing fresh-task path runs.
- Continuation rendering shared (`agent/task/continuation.ts`) with a stable section marker.
- 30-second supervisor sweep finds expired waits and resumes them with a "no response within X" timeout continuation. Agent decides whether to give up, retry, or report.
- System prompt: new "Multi-hop coordination" section teaches the canonical shape (ack on A -> ask on B -> task_await_response -> continuation -> forward back). 42 baseline tools total (added `task_await_response`).

Bug caught on first end-to-end run: `external_response` blockers survived across task runs (registry is process-scoped, not per-task). The resumed task hit the pre-iteration check, saw the stale in-memory blocker, and exited immediately as still-parked. Doug's screenshot showed Simon stuck after Hobby's reply. Fix: clear `external_response` blockers at the start of every `run(task)`. Confirmed clean on the retest (90s round-trip).

18 unit tests for the matcher + serialization + continuation rendering, plus the count test in `baseline.test.ts` bumped to 42.
