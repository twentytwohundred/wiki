## What shipped (all merged on `main`)

### Substrate cleanup (morning)

**#230 ... lock-based PID liveness.** Replaced the historical `kill(pid, 0)` liveness check with `proper-lockfile` lock holdership across the supervisor and every Agent. Eliminates the stranger-PID hazard — recycled OS PIDs can no longer fake liveness because the check asks "is this lockfile held?" instead of "is this PID alive?". Migration is operator-walkable: a daemon from a pre-lock release is detected and refused with a clear "stop the old daemon, remove the stale pidfile" message. This morning's restart on Doug's box exercised the migration path; worked exactly as designed. Decision record at [[2026-05-21-pid-file-liveness-via-lockfiles]].

**#233 ... `install.sh` auto-configures `~/.npm-global`.** Friction surfaced by Simon's install attempt on Ubuntu yesterday: system `npm` at `/usr` requires sudo, the old installer printed three options and bailed. Engineers can navigate that; Normals close the terminal. New behavior detects the situation, narrates it in plain language, and auto-fixes (shell-aware: bash → `~/.bashrc`+`~/.profile`, zsh → `~/.zshrc`, fish → `~/.config/fish/config.fish` with `set -gx` syntax). Interactive prompts when stdin is a TTY; auto-applies on `curl ... | sh`. Idempotent.

**#234 ... chaos test flake, root-cause fix.** The `supervisor-bounce-survival` test flaked ~1 in 5 CI runs. Root cause: the test raced `supervisor.shutdown()` against the Agent's in-flight `agent.register` RPC response — the supervisor closed the UDS listener before the response landed, the Agent saw "connection closed" before its heartbeat loop was up, and exited 1. The Agent's heartbeat-reconnect path would have recovered from this, but it isn't installed until AFTER register returns. Fix: a `TWENTYTWOHUNDRED_HEARTBEAT_INTERVAL_MS` env override + wait-for-advancing-heartbeat predicate in the test. Five-for-five green locally after the fix. Doug's call: "once and for all," not retries in CI.

**#235 ... `@eslint/js` v10 adoption + 26-violation sweep.** Dependabot opened the bump (#232) with CI red on `preserve-caught-error` (21 hits) and `no-useless-assignment` (5 hits). Adopting the rules instead of suppressing: `preserve-caught-error` makes us pass `{ cause: err }` on every throw inside a `catch`, so debug sessions see both the symptom and the underlying error. `no-useless-assignment` killed dead `let x = null` initializers that were immediately overwritten by both try/catch branches. Closed #232 (superseded). The `cause` chains are now permanent debug ergonomics across the runtime.

**#236 ... device-code OAuth substrate + xAI provider + CLI.** Generic RFC 8628 device-flow runner with PKCE S256, reusable for any future public-client OAuth. xAI-specific config that loads the OIDC discovery doc at flow time (no hardcoded endpoints; defensive checks reject any doc that drops `device_code` or `S256`). Fleet-scoped sealed token store at `<home>/state/oauth-tokens/xai-oauth.json` — AES-256-GCM + HKDF over the per-instance master key with a fleet-scoped HKDF info string, distinct from the per-Agent vault namespace. xAI provider lookup reads the bearer; refresh service refreshes within 120s of expiry using the public-client refresh grant. CLI: `2200 oauth xai login | status | logout`. Decision record at [[2026-05-21-xai-grok-oauth]].

**#237 ... Grok-First sign-in tile + daemon HTTP endpoints + first-run integration.** New tile at the top of the Settings page with "Sign in with X / SuperGrok," inline device-code flow (large user code, verification URL one-click, the "this will say 'Grok Build', that's expected" note built into the UX). Four daemon endpoints (`/api/v1/oauth/xai/login/start`, `/login/status?session=<id>`, `/status`, `/logout`) backed by an in-process `DeviceFlowSessionManager` that holds PKCE verifier + device_code state across browser polls. First-run wizard now offers Grok sign-in inline after user-identity mint (default yes), so a new install can leave setup with a working Grok credential without ever pasting an API key.

**#238 ... `xai-subscription` as a distinct provider + "Subscriptions" optgroup in the model picker.** Earlier auto-prefer-OAuth-when-token-present was the wrong design: it hid the credential choice from the operator. Reverted that. `xai-subscription` is now a sibling provider to `xai` — same OpenAI-compatible chat-completions transport, different credential source, distinct entry in the Identity. The picker shows a "Subscriptions" optgroup pinned at the top with the subscription entry. `ProviderCatalogEntry.category: 'subscription' | 'api-key' | 'local'` drives the grouping. Resolution for `xai-subscription` fails loud if not signed in (no silent fallback to API key — the operator chose subscription).

**#239 ... three-layer regex hunt + official Grok logo.** Doug tried to pick the subscription model and hit a 422 validation_failed. Root cause: three separate regexes each rejecting hyphenated provider names:
1. `PutAgentModelBody.provider` at the HTTP route layer (`/^[a-z0-9]+$/`)
2. `ModelProviderSchema` in the Identity loader (`/^[a-z0-9]+(:[a-z0-9][a-z0-9-]{0,49})?$/`)
3. `ModelIdSchema` in the wire protocol (`<provider>/<model_id>` form)

Widened all three to accept hyphenated bases and endpoint colons, added a regression test in the Identity loader that explicitly asserts `xai-subscription` passes. Also replaced my Saturn-style placeholder logo with the official Grok mark Doug dropped in my inbox (`apps/web/src/assets/grok-logo.svg`).

**#240 ... auto-restart Agent on model switch.** Discovered live: switching the model writes the Identity, but the Agent's in-memory `LLMProvider` is constructed at boot and won't pick up the new binding until restart. Doug's call: auto-restart. The picker mutation now runs three steps inline (PUT identity → POST stop → POST start), with a spinner during the swap and a clear error tip if start fails. Validated by Doug mid-session: test-6 cleanly swapped through `xai-subscription/grok-4.3` → `deepseek/deepseek-reasoner` → `xai-subscription/grok-4-fast`, each with a mic-check confirming the new binding.
